Since 2026-10-18 (codegen-test-plan.md P1-P4) the tests are split by suite: `tests/compiler/` is the gtest suite
(run with `tests/compiler/run.sh`, formerly `.tools/run-unit-tests.sh`), and `tests/codegen/` holds the end-to-end
hardening checks that used to be `.tools/check-*.sh`. The `spp_tests` glob reads only `tests/compiler/`.

`bash tests/codegen/run.sh [spp] [name ...]` runs every `check-*.sh`, or those named (`run.sh <spp> sls seal`).
All eight took 2m58s locally (~60 build+run cycles, ~3 s each). Each check sources `tests/codegen/lib.sh`:
`new_project dir "<extra toml>"`, `add_ffi dir pkg source.c|.cpp <<stub`, `build_project name dir mode` (sets
`EXE`/`OBJ`, returns 1 on failure - caller bumps `failures`), `run_exe exe log` (sets `RC`, never piped), `ok`,
`fail msg [log]`, `require_x86_64`, `finish`. The project is named after its directory, and so is the executable.
`SPPC_LIB=` works for every check. std is copied from `tests/test_outputs/vcs`, or cloned once per script when
there is no fixture (CI).

CI (P6): `_lane.yaml` job `codegen` (input `codegen: true`, on in pr.yaml and post_merge.yaml Linux lanes) runs
`bash tests/codegen/run.sh build/spp`. Advisory (`continue-on-error`) until a green run proves the hosted kernel has
mseal/MDWE; then delete that line. The maintainer decided 2026-10-18 the rest of codegen-test-plan.md (C0-C7, the Python
driver) is backlog only - don't start it unprompted.

`check-intrinsics.sh` (P4.6, 2026-10-21) is the big one: ~23k cases generated by `tests/codegen/intrinsics.py` (emit +
judge), 61 programs x dev/rel, ~2.5 min at `JOBS=6`. Its known bugs live in `KNOWN` in intrinsics.py (reported
`known`; an entry none of whose cases fail reports `FIXED` and fails the check - remove it with the fix). A new
intrinsic in `codegen/builtins.cpp` fails it until it has cases or an `EXCLUDED` reason. lib.sh's `WORK` is deleted on
exit, so to read a failing program's build log, re-emit and build it by hand.

**How to apply:** a new hardening measure gets a `check-<measure>.sh` on `lib.sh`, with a negative control (the
key off) - see `one-hardening-measure-at-a-time`. Run the one check while iterating, `run.sh` before handing over.
