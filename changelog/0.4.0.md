# S++ 0.4.0

## Type system

The type system has been rebuilt around interned identities. 0.3.0 gave a written name a record of what it resolved to;
now every type and `cmp` value has an identity of its own, and analysis compares, substitutes and matches those rather
than syntax trees.

- A type is a `TypeId`: one interned key, so two types are equal exactly when they are the same pointer. A `cmp` value
  is a `CompId` in the same way, keyed by the value it folds to.
- `TypeRef` is the one way to read a type: a written type in a scope, a symbol read through the bindings in force, or an
  identity looked up as is. Lookup never instantiates anything; making an instance is a separate, explicit step.
- Substitution rewrites identities by parameter, and a variant's members, a tuple's elements and a variadic pack's
  contents are all rewritten in place, with nothing re-spelled and re-resolved on the way.
- Aliases and `use` imports resolve to their target where they are read, while keeping the name they were written with
  for messages.
- The legacy AST comparison and inference helpers are gone, replaced by the identity-based versions.

### Generic inference

- Generic inference is a single solver for every generic declaration. It takes what is given in order of precedence
  (written arguments, then the receiver, then the enclosing `sup` block, then a pinned `Self`), unifies each argument
  with its parameter by identity, then repeats over `cmp` value types and constraints until nothing new is bound.
- One pattern matcher (`UnifyTypeIds`) handles everything that matches a generic pattern: attaching `sup` blocks,
  binding a method's generics from its receiver, function values, and the overlap and conflict checks between `sup`
  blocks.
- A pattern read inside an instantiated block binds only its own declaration's parameters, not the caller's that happen
  to be visible there.
- `Var[..]` packs are matched properly: a variadic member takes whatever members the fixed ones leave, so `Opt[USize]`
  is recognised as `Copy` again.
- The solver finds every parameter by identity, never by name. A method generic with the same name as one of its `sup`
  block's generics is now inferred from the arguments instead of taking the block's binding, so `r.ior_(o)` with
  `r: Res[S32, Bool]` and `o: Res[S32, U8]` compiles.

### Overload resolution

- Overloads are ranked, not just passed or failed. Each argument is ranked as it is checked (exact, widened, bound to
  an inferred generic, or forwarded). After the return type the context asks for has narrowed the candidates, the
  overload no worse anywhere and better somewhere wins. When all else is equal, the less variadic one wins: a fixed
  parameter beats `..x: T`, which beats `..x: Ts`. A call is ambiguous only when several candidates are left after
  that.
- `g[T](..xs: T)` and `g[..Ts](..xs: Ts)` are no longer reported as conflicting.
- Functions whose names differ only by `_` or case (`foo1` and `foo_1`, `fooBar` and `foobar`) shared one overload set,
  so `foo1(true)` could call `foo_1`. Each name is now its own.
- A closure held in an attribute can be called (`h.f(1)`). It used to be given `h` as `self` and fail with too many
  arguments.
- `Self` is the receiver's type whenever the receiver isn't the declaring class. An inherited method called through a
  forwarding type, or an inherited associated function (`Square::describe()`), used to run with `Self` as the base
  class. That could reach the base's method instead of the override and compile to the wrong call with no error.
- A `Void` parameter is removed from a function when it is declared, so `fun f(x: Void)` has one shape throughout,
  rather than changing once something called it.

## Language

- **Zero types:** a zero type has exactly one value, written as the type's own name. Constructing one with an object
  initialiser is now "Object Initialiser Zero Type" (E115).
- **Copy and Drop markers:** only the package that declares a type may superimpose a marker over it, because a marker
  decides how every value of the type is handled. Doing it from another package is "Superimposition External Marker
  Extension" (E111).
- **Generators:** a finished generator answers the `GenDone` sentinel rather than `None`, so `None` can be yielded like
  any other value. A generator whose yield type contains `GenDone` is "Yield Type Contains GenDone" (E110).
- **Default values:** a default can't name another parameter, because it is copied into the caller, where that name
  means something else. This is "Default Value Names Parameter" (E113).
- **Pattern guards:** a guard can't move a value: it runs before its branch is chosen, so if it answers false, the next
  branch would run with that value already gone. This is "Pattern Guard Moves Value" (E114).
- **Char literals:** `\x` escape sequences are supported, and a char literal that holds more than one character is
  "Char Literal Length" (E112).
- **Renames:** errors that said "Comptime" or "Compile Time" now say "CompTime" to match the `cmp` keyword.
- **`$` in names:** a written `$` is a syntax error. `$` names are reserved for what the compiler generates, and a
  user's `cls $Foo` was treated as one: made copyable and given no `Self`.
- **Intersection types:** `A and B` in a type position is a syntax error, "Intersection types ("A and B") are not
  supported". It used to reach a part of the compiler with nothing to make of it.

## Pattern matching

- **Exhaustiveness:** a `case` that covers every value of its subject needs no `else`, as a value or as a statement.
  Coverage is worked out through every position of a pattern, not only its top level: `Some[Some[T]]`, `Some[None]` and
  `None` together cover `Opt[Opt[T]]`, and the four `Some`/`None` corners cover `(Opt[S32], Opt[S32])`. A `case` that
  can fall through still needs its `else` where it is a value, and has type `Void` otherwise. A guarded branch covers
  nothing.
- **Unreachable branches:** a branch that can never match - after an `else`, after the subject is fully covered, or
  repeating what earlier branches took - is "Case Branch Unreachable" (E116), pointing at the branch that covers it.
- **The short form:** `case x is P { .. }` is now a pattern-matching `case` over `x` rather than a boolean `case` over
  an `is`, so a pattern that cannot fail (`case p is Point(x, y, z)`) needs no `else`, and an `else` after one is
  unreachable.
- A `case` that every branch leaves by `ret` ends its function, so no trailing `ret` is needed after it.
- A destructure whose type refines a field that its binding also matches
  (`is Some[Some[S32]](val=Some[S32](val))`) now covers what it matches, instead of nothing.
- `== literal` branches take part in coverage like a destructure's literal, so `== 1` twice is unreachable, as
  `== 16` after `== 0x10` is.
- Literals in patterns are compared by value, not by how they are written.

## Memory analysis and control flow

Ownership checking has been rebuilt, the same way the type system was: places, states and borrows are identities and
values joined where paths meet, rather than spellings and flags. Several holes in the rules are closed on the way, so
code the compiler used to accept can now be rejected.

### The model

- **Places by identity:** a place is a root symbol and a path of fields, indices and calls, compared by identity rather
  than by text, so two spellings of one place are the same place and a step through a method call is treated as
  possibly reaching anything under its root.
- **One binding per `let`:** a `let` that shadows another is its own symbol from where it is written, so a shadowed
  value keeps its state and is still held to the linear rule.
- **States joined where paths meet:** each path through a `case` or a loop has its own state, and they are joined, so a
  value moved on only one path is reported as such ("Inconsistently Initialized Memory Use" E8) naming both paths.
  `defer` runs against the state at each exit it is reached on.
- **Loops are joined at their head:** the first iteration is checked from the state before the loop. Every later one is
  checked from the join of the ways back round: the end of the body, and every `skip` with what it left moved or
  borrowed. This repeats until nothing changes. The way out through the condition, and so the `else` block, starts
  from the state before the loop joined with those.
- **Loans:** a borrow is a loan held by whatever holds it - a borrow binding, a pattern bound by borrow, an index
  borrow, a closure, a generator or a future - and every conflict is checked against those loans in one place.
- **A loan ends at its holder's last use:** a holder that is never used again no longer blocks what it borrowed, so
  `let a = v[mut 0]` followed by `v[mut 1]` after `a`'s last use is accepted, as is `ret self` after a pattern's
  `&val` is done with. A conflict is reported when the holder is used again after it.
- **Borrow lifetimes as loans:** a value given a borrow - by a `let`, an assignment, a closure capture, or a block or
  `case` value - may not outlive what it borrows ("Borrow Lifetime Increase" E76). Closures, `case` values and block
  values used to slip past this.

### Rules that are new or stricter

- **Linear temporaries:** a non-`Copy` temporary must be consumed by the expression that makes it. Borrowing one
  (`&mk()`, `mk().peek()`), comparing two (`Str::from("a") == Str::from("b")`), reading a field off one or matching on
  one in a `case` that keeps it is "Linear Value Not Consumed" (E94). Bind it with `let` and consume it after.
- **Writing over a live value:** `x = f()` while `x` holds a non-`Copy` value drops it, and is now E94; consume it
  first. Writing through a borrow (`self.a = ..`, `x@ = ..`) cannot take the old value first, so it is E94 too:
  exchange it with `std::mem::ops::replace`, which hands the old value back.
- **Holders are owed:** a closure that captures by `&mut`, a generator that borrows, or a future that is not awaited
  must be consumed by the end of its scope (E94). `std::mem::ops::drop` consumes it and ends what it borrowed there;
  passing it anywhere else is still "Moving Escaping Borrow Memory" (E85). Dropping a future waits for its task, so
  what it borrowed is free again straight after.
- **`loop ... in`:** the iterator behind the loop is dropped on every way out of it, ending its borrows there, so
  `loop x in v.iter_mut() { .. }` followed by `v.append(..)` is accepted and the generator's frame is freed.
- **Destructuring a temporary:** `let P(a, ..) = mk()` that leaves an owned field behind is "Destructure Skips Owned
  Part" (E105), as it already was for a named value.
- **Immutable `let` given its value later:** it may be given one value on each path, so assigning it in both branches
  of a `case` is fine, but assigning it again after a path that already did (or after its value was moved) is "Invalid
  Mutation" (E4).
- **Inherited default methods are checked per type:** `Clone::clone_from`'s default writes over `self@`, which drops the
  old value of any type that owns something. The error is reported at the call, naming the type; override
  `clone_from` to exchange the value instead.
- **Two ways to one place in one call:** a closure or generator given to a call brings what it borrows with it, so
  `run(&mut c, &mut x)` with `c` capturing `&mut x` is "Memory Overlap Usage" (E20).
- **Pattern guards** are checked against everything in scope, including shadowed values.
- **Calling a `FunMov` through a borrow:** a `FunMov` is consumed when called, so calling one held through a borrow
  (`(v[i])()`, a `&FunMov` or `&mut FunMov` parameter) moves it out of the borrow (E7, "Move From Borrowed
  Memory"), as a `self`-taking method already did. A `FunMut` through `&mut` and a `FunRef` through either borrow
  are still fine.
- **`skip` carries its state to the next iteration:** a part moved on the way to a `skip` and moved again by the next
  iteration was missed, and so was a borrow still held at a `skip`. Both are reported now.

### Fixed

- Unreachable code and fall-through checks now share one divergence analysis.
- `self` being moved out from behind a borrow, closures capturing loop variables, closure capture storage and name
  mangling, `defer` in some exit paths, and aliased subjects narrowing incorrectly in `case`, including
  variant-to-variant narrowing in a destructure.
- A `case` branch that keeps a temporary and leaves by `ret` or `exit` is now reported like one that falls through.
- A closure can be passed by borrow as a concrete function type (`take(&c)` for `c: &FunRef[..]`, `&mut c` for
  `&mut FunMut[..]`); calling through a `&FunRef` parameter no longer asks for `&mut`.
- An inherited default method's parameters written as `Self` (`source: &Self`) are read as the implementing type, so
  calling an inherited `clone_from` no longer fails with a type mismatch.
- A move error now points at where the value was moved.
- Borrows and partial moves are compared by place, not by name, where paths meet, so a shadowed `x` and the `x` it
  shadows are no longer read as one place across a join or a loop pass.

## Codegen

- Variant and function-value coercion is added wherever a typed slot is written, fixing missing coercions in several
  places.
- Fixed: the result of a `case` expression is now extracted correctly, values yielded from loops are fixed, and
  coroutines use the new sentinel.
- Casting is much cheaper inside the compiler.
- `&mut` parameters are marked `noalias`, now that the memory analysis guarantees nothing else reaches the same place
  during the call. Runtime tests cover each way an alias could arise.
- Fixed: a closure's environment gave a borrowed capture a slot the size of the value rather than of a pointer, so a
  `&` capture of anything narrower than a pointer read back garbage. A by-value `FunMov` closure leaked its environment
  each time it was called; it is now freed by the call. Generator frames behind `loop ... in` are now freed.
- `std::mem::ops::swap` is an intrinsic.
- Fixed: a `FunRef` that captures by `&` passed where a `FunMov` or `FunMut` is expected freed its stack environment
  when called or dropped (`free(): invalid pointer`). A closure's environment now records whether it is on the heap or
  the stack, and is freed only when it is on the heap and owned.
- Fixed: `Void` fields in an object initialiser, and a `cor` returning `GenOnce`, whose `gen` is lowered to a return.
- Core types are recognised by identity in codegen rather than by their scope path.

## Standard library

- `Vec::from_iter` (behind every `collect[Vec[..]]()`) now collects; it returned an empty vector, which is why
  `Path::components()` was always empty.
- `RawBuf::take_at` answers `None` only past the capacity: the owner tracks which slots hold a value.
- Updated for the stricter ownership rules: `GlobalAlloc` is `Copy`; `bigint`, `biguint`, `io` and `path` exchange
  values with `std::mem::ops::replace` instead of writing over them; `Arr::swap` and `Vec::swap` consume what they
  take.

## Tooling and IDE support

- `spp build` has new options:
  - `--message-format=json` prints one diagnostic object per error, including its visibility.
  - `--analyse-only` stops after analysis: errors are reported, nothing is generated.
  - `--skip-vcs` skips fetching `[vcs]` dependencies.
  - `--index-file <path>` (repeatable) and `--index-project` report what every name resolved to, which powers completion
    and hover in the IntelliJ plugin.
- Analysis can continue past an error, so one compile reports every independent error in a file instead of stopping at
  the first. Errors from Stage 6+ are included.
- Error spans are measured from token positions, fixing identifier lengths and the span of `self`.
- `spp init` now returns an error exit code when it fails, and `spp test` and `spp clean` do too when run outside a
  valid project (they used to exit 0 having done nothing).
- `spp test --runner "<command>"` runs the test executable under a command such as valgrind, with the memory cap lifted.
- **FFI libraries per target (breaking):** a package ships one library per target, in a folder named
  `<arch>-<os>[-<env>]`: `ffi/sppc/x86_64-linux-gnu/libsppc.so`, `ffi/sppc/aarch64-linux-gnu/libsppc.so`,
  `ffi/sppc/x86_64-windows-msvc/sppc.dll`, `ffi/sppc/aarch64-macos/libsppc.dylib`. The file name stays the same in
  every folder, because it is the name the loader asks for. The old flat `ffi/sppc/libsppc.so` is rejected.
  `spp validate` checks every target folder: its name must be the compiler's own spelling, so `arm64-linux-gnu` and
  `x86_64-darwin` are errors, and it must hold the library named for its platform. A build fails at link time if a
  package has no library for the target being built, and lists the targets the package does ship.
- The unused `--dir` option is removed: `spp` works in the current directory.
- The duplicate-symbol error no longer fires on prelude imports.
- **Internal compiler errors:** a state the compiler should never reach now stops the compile with a report rather than
  carrying on with a plausible value, which used to surface as a wrong error far away or as wrong code. The report
  gives the message, the source it was working on, the compiler's own file, line and function, a stack trace (on GCC
  builds), and asks for it to be reported. With `--message-format=json` it is a diagnostic with code `ICE`.
  Assertions are on in release builds too. Every site that used to recover from such a state has been audited, and
  25 now raise one.
- **Errors quote the right file:** every source position names the file it came from, so an error with blocks from
  several files quotes each from its own. An error used to quote a block from another file at the same position in
  the wrong file, or at the end of it.
- A process that compiles more than once, such as the test runner or a language server, no longer carries anything
  from one compile into the next. Each compile has its own LLVM context, so a class laid out by an earlier compile is
  no longer reused. Type and `cmp` identities are freed with their compile, so memory no longer grows by about 50 MB
  per compile.

## CI

- Every released binary has passed its own platform's tests. Linux x64 ships the binary the master pipeline tested,
  and Linux arm64, macOS and Windows each build, run the test suite and STL conformance before their binary is
  published.
- Releases carry a `SHA256SUMS` file and build provenance attestations. Verify a download with
  `gh attestation verify <file> --repo SamG101-Developer/spp`.
- Released binaries no longer need anything from the build machine: `libstdc++`, `libgcc` and `mimalloc` are linked
  statically, and the build fails if a binary needs a library the operating system doesn't ship.
- The pipeline graph shows each stage as its own job: one build per platform, then each gtest shard, STL conformance
  and each cross-codegen target, so a failure says which stage broke. A test job's summary lists its failed tests.
- The compiler is built once per platform instead of once per test shard, and cross-codegen builds once instead of
  once per target.
- Test jobs install no toolchain. They run the build job's binaries after checking them against digests that only the
  build job can publish.
- A pre-commit check holds every workflow to the pipeline's security rules: pinned actions, least-privilege
  permissions, harden-runner first, no persisted checkout credentials, and no artifacts from other runs.
- The CI scripts are organised by stage, and duplicated setup has moved into shared helpers.
- The Linux lane runs chosen S++ test groups under valgrind, which catches leaks, invalid accesses and double frees in
  generated code that the unit tests never run. It is advisory for now. Valgrind is pinned in
  `.github/dependencies.toml` and built from the release tarball, rather than taken from apt.
- A nightly lane builds the compiler with ASan, UBSan and LSan and runs the memory, ownership, pattern-matching,
  generics and closure suites under them. It is too slow for a pull request.
- CI no longer downloads and verifies a prebuilt Boost on every runner, and its pins are gone from
  `.github/dependencies.toml`.
- A test job's summary counts its shard's results correctly, and the valgrind lane installs the C library's debug
  info and runs the project's own std tests.
- Debug and sanitizer builds turn on the C++ standard library's assertions (`_GLIBCXX_ASSERTIONS`).

## Internals

- The analysis utilities have been reorganised into focused modules and cleaned up: dead and single-use functions have
  been removed, and the AST checks have been merged into `ast_utils`.
- Uids no longer include addresses, so output is stable from run to run.
- The legacy memory trackers are gone: one flow state per function body holds every symbol's state and every loan, and
  loop and `defer` bookkeeping lives on it rather than on the shared metadata.
- Boost is no longer a dependency. The parser used only its preprocessor library, in two macros: `PARSE_ALTERNATE`
  now loops with a short `__VA_OPT__` macro of its own, and `CREATE_AST` is replaced by a function template that
  moves its arguments in. Building from source no longer needs Boost installed.
- Overload resolution is one solver per call: the call's target and candidates are found once, each candidate is
  checked into a result rather than by exceptions, and overrides are worked out once per class and name.
- Monomorphisation is one engine for classes, functions and `sup` blocks, sharing its steps. A function instance
  copies its signature, and a `sup` instance its members' signatures, rather than every body they then throw away.
  Function instances are found by identity rather than by a scan.
- The compiler uses its own aliases for library types throughout (`Vec`, `Opt`, `Str`, `Func` and so on), enforced by
  a pre-commit check, plus a small vector for short-lived lists on hot paths. Nothing is added to namespace `std`.
- Many more unit tests, including LLVM verification of generated code.
