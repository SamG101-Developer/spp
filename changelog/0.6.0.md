# S++ 0.6.0

## Performance

- **NumEx is optimised and rewritten:** the big-number library behind every literal and comp-time value was installed
  without a build type, so it ran unoptimised in every build of the compiler, and took 23% of a compile. Division was
  done a bit at a time, copying and negating at each step. It now uses Knuth's Algorithm D, `*=` allocates `n + m` limbs
  rather than `n * m`, `+=` and `-=` work in place, and text is read and written many digits at a time. A `BigDec` read
  from text only cancels the factors of 2 and 5 its denominator can have, rather than running a whole `Gcd`. NumEx is
  0.6% of a compile now, and a project that took 4.39 s builds in 2.92 s.
- NumEx, GenEx and ColEx build as `Release` when no build type is given, so an install cannot quietly be unoptimised.
- **`$` mocks attach their `sup` blocks on first read:** the sweep used to attach every one, and about 96% were never
  read. This takes a further 5.3% off a compile (3.04 s to 2.86 s), with identical generated code.

## Fixed

- **A use-after-free while attaching `sup` blocks:** some sets of source files crashed the compiler, or failed in `std`
  with errors like "Identifier Unknown" (E26) or "Linear Value Not Consumed" (E94) that had nothing to do with the code.
  Files are compiled in sorted order, so a project could start failing just by adding or renaming a file. About 7% of
  shuffled file orders of a test project failed; now none of the 43 tried do.
- **Paths with spaces:** `spp run`, `spp test`, linking and `git` commands now quote the paths, URLs and branch names
  they pass to the shell, where a space used to split one argument into two.
- **Windows exit codes:** `spp run` and `spp test` read a program's exit status as a POSIX wait status everywhere, which
  misread it on Windows. Each platform now decodes its own.
- **Windows crash re-runs:** when a test binary crashes, `spp test` re-runs each test in its own process, which set
  `SPP_TEST_ONLY` in POSIX syntax and so could not work under `cmd`.
- **A dependency removed from `[vcs]` kept compiling:** its folder was still read, and its library still linked, until
  the folder was deleted by hand.
- **Stray files in a dependency compiled:** any `.spp` file in a checkout was read, such as one under `examples`, under
  a namespace named after its parent folder. Only a dependency's `src`, `tst` and `ffi` are read now.
- **An invalid dependency passed validation:** the error was printed and the build carried on. It now stops the build.
- **A project under a folder named `vcs` was misread as a dependency:** this got past the rule that only a type's own
  package can make it `Copy` or `Drop`, and left the project out of IDE indexing.

## Dependencies

- **A dependency's own dependencies are fetched:** `spp vcs` reads each dependency's `[vcs]` and carries on through what
  it declares, cycles included. Everything lands flat in `vcs/<name>`, and is compiled and linked, ffi libraries too.
  `spp test -l` and `--all-libs` can test any of them.
- **A dependency is one repository and branch (breaking):** one name declared with a different `git` or `branch`, by any
  two packages, is an error naming both, rather than one being chosen. URLs compare as written.
- **A package can only name what it declares (breaking):** a module naming a package its own `spp.toml` does not declare
  is "Dependency Not Declared" (E121), and that includes `std`, and a library naming the project using it. A value of
  an undeclared dependency's type can still be held and used, as long as `b::...` is not written.
- **Every package declares `std` (breaking):** a project or library that does not is told so by name, rather than
  failing at a prelude line, or with every `std` symbol undefined. A project named `std` is exempt.
- **A top-level namespace is one package (breaking):** one shared by two dependencies, or a dependency and the project,
  or used by both source and an ffi package, is an error before anything is parsed.
- **`[vcs]` records are checked (breaking):** `git` is required, `branch` is optional, and anything else is an error
  rather than ignored. A name can only hold letters, digits, `_` and `-`, so it cannot leave `vcs`, and `git` and
  `branch` cannot start with `-`, which git would read as an option.

## Command line

- **Dependencies are checked before building (breaking):** `spp validate` and `spp build --skip-vcs` report a declared
  dependency that has not been fetched, and tell you to run `spp vcs`. A broken checkout no longer stops the fetch that
  would repair it, as validation before a fetch only looks at the project.
- **Environment variables are checked (breaking):** spp stops at startup, before doing anything, on an `SPP_` variable
  it does not know or one with a malformed value, rather than silently ignoring a typo. `SPP_CI_` names are exempt. This
  includes `--help` and `spp config`.
- `spp config` lists the environment variables along with the `spp.toml` keys: `SPP_BACKTRACE`, `SPP_MEMORY_LIMIT_KB`,
  `SPP_NO_NETWORK_CHECK`, `SPP_TEST_MODE` and `SPP_TEST_ONLY`.
- `spp init --force` (`-f`) initialises a directory that is not empty, keeping any `spp.toml` and `main.spp` already
  there.
- `spp test` gains short forms: `-a` for `--all-libs`, `-r` for `--runner`.
- `--target` with an unknown triple suggests 25 targets rather than 8, the ones CI builds, including macOS, Windows and
  FreeBSD. A pre-commit hook keeps the two lists the same.
- `--mode` shows its choices as CLI11 prints them (`{dev,rel}`), derived from the modes the compiler has.
- `build` in `spp.toml` accepts any case (`LIB`), and an invalid one lists what is allowed.

## CI

- The nightly sanitizer job failed on every test, on a null pointer read in `checked_ptr_cast` (`ptr.ixx`), which
  stopped it finding anything else. The cast now answers null for a null pointer.
- Environment variables used only by CI are renamed to `SPP_CI_`, leaving `SPP_` for what the compiler reads. A
  pre-commit hook, `env-vars`, checks every name used in the repository is registered.
- CodeQL also scans the Python scripts.
- Bumped: `mimalloc`, `json`, `magic_enum`, `stringzilla`, `ColEx`, `GenEx` and `NumEx`.

## Internals

- New `spp.compiler.dependencies` is the one reader of `[vcs]`, and the CLI, the module tree and the ffi checks all ask
  it, where each used to work dependencies out from folders and paths. `tests/codegen/check-transitive-deps.sh` checks
  it end to end with real git repositories.
- A module's LLVM context is created at the start of stage 10, its first use, so a compile that stops after stage 8 (IDE
  indexing, or one with errors) does not make them.
- The C++ test harness finds `src/main.spp` by its path, rather than taking the first module.
- `BuildMode` and `BuildType` are `enum` types in `spp.compiler.out_layout`, used by every field and parameter, with
  their names derived by `magic_enum`, which replaces the fixed lists in the CLI and `!cfg`. Text is converted once,
  where a user writes it.
- New `spp::utils::env` is the one registry and reader of environment variables, and `spp::utils::shell` the one way to
  run a shell command and quote its arguments. Pre-commit rules ban reading the environment or calling `system`
  directly.
- The `sys` wrapper module covers the environment, file access and locks, the dynamic loader and exit statuses across
  POSIX and Windows, and `files` and `llvm_artefact` use it rather than platform headers.
- `CheckTargetSupport` moved from the CLI into `features`, taking a `TargetFacts` rather than asking codegen.
- Moved to the new GenEx API, where `views::cast_dynamic` and `actions::pop_front` are closure objects. The hand-rolled
  helpers in `utils/algorithms` are replaced by GenEx.
- The `cli`, `features`, `files`, `compiler`, `compiler_boot`, `cfg`, `ffi`, `llvm_target`, `llvm_artefact`,
  `module_tree` and `out_layout` modules are reformatted and documented, and dead code is removed, including the
  separate test count.
