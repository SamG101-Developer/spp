# S++ 0.6.0

## Language

- **A pack is not a value (breaking):** a function's variadic parameter (`..xs: Ts`, `..xs: T`, `..xs: &Ts`) is a list
  of values, not a tuple. It can be spread (`f(..xs)`), indexed (`xs.0`), collected into a tuple (`(..xs)`) or folded,
  and any other use of it whole is "Pack Not A Value" (E123). To migrate:
  - `drop(xs)` becomes `drop(..xs)`, through `std`'s new variadic `drop`;
  - returning or storing the pack, `ret xs`, becomes `ret (..xs)`, with the return type `Tup[Ts]`;
  - passing it on as one argument, `g(xs)`, becomes `g((..xs))`, or `g(..xs)` to pass its elements.
- **A type pack is not a type (breaking):** `..Ts` names a list of types, so it can only be a generic argument
  (`Tup[Ts]`), a tuple or variant member (`(A, Ts)`, `A or Ts`) or a variadic parameter's element type (`..xs: Ts`).
  `t: Ts` and `-> Ts` are "Pack Not A Type" (E124); write `Tup[Ts]`.
- **A pack's convention is each element's:** `..xs: &Ts` takes a borrow per element, and each instance gives every
  element a parameter of its own, so a pack of borrows passes pointers, with no tuple built at the call.
- **Folds over packs:** a binary operator folds over a function pack (`.. + xs`, `xs + ..`), checked in the generic
  function by the element type's constraints, and a call folds over one (`f(x, xs)..`), one call per element. Packs
  folded together must be the same length (E126), and a spread inside a fold is E125. A call fold over a function
  returning `Void` is `Void`, so `drop(xs)..` is a statement; any other is the tuple of the results.
- **Pairwise pack constraints:** a constraint naming its own pack, `..Ts: Add[Ts]`, holds when every element meets it
  with every other, so a fold over a pack of mixed types is proven at the call.
- **A comp pack spreads in its template:** `h(..n)` for `cmp ..n: Bool` was "Expansion Of Non-Tuple" (E19). Like a
  function pack's, the spread stands for every length, so the callee needs a variadic parameter to take it. Folds
  over a comp pack work in its template too (`.. + ns`, `twice(ns)..`), and so does reading an element off its tuple
  (`let t = (..ns); t.0`).
- **A comp pack is not a value (breaking):** like a function pack, `cmp ..ns: Bool` used whole (`let t = ns`,
  `g(ns)`) is "Pack Not A Value" (E123), where it was its tuple; write `(..ns)`. Forwarding it as a comp generic
  argument (`A[ns]`) is unchanged.
- **A call fold evaluates its receiver and its other arguments once (breaking):** `make().m(xs, arg())..` runs
  `make()` and `arg()` once, not once per element, as a binary fold evaluates its operand once. A method that
  consumes its receiver, or an unfolded argument passed by value, is therefore used up by the first call, and the
  second is "Uninitialized Memory Use" (E5), as when the calls are written out. A literal is still given to each call.
- **A fold over a field reads it in place:** `.. + self.items` and `f(self.items)..` read the field where it is, as a
  spread does, instead of copying it into a temporary first, so its elements can be moved out of an owned `self`.
- **A variant's members are listed in tag order** in messages and in the types the compiler writes out, the one order
  the compiler keeps for them.
- **A spread is the last positional argument:** one followed by another positional argument is "Spread Not Last"
  (E122), where it used to be "too many arguments."
- **A pack is never named (breaking):** a variadic parameter is last and takes the trailing arguments, so naming it
  (`P[Ts=(S32, Bool)]`, `Var[Variants=(S32, Str)]`, `A[ns=(1, 2)]`) is "Argument Name Invalid" (E46); write the
  elements, `P[S32, Bool]`. An instance is printed the same way, its pack's elements in place, in messages and in
  mangled names.
- **Variadic arguments may follow keyword arguments,** as in Python: `P[A=S32, Bool, U8]` and `f(a=1, 2, 3)`, where
  each trailing positional goes to the variadic parameter. One that would bind a fixed parameter is still "Order
  Invalid" (E18).
- **Tuples and variants are ordinary classes over a pack:** a tuple's own `sup` blocks bind its pack like any class's,
  so a method over `Tup[Items]` is an ordinary method, and the tuple special cases in the compiler are gone.
- **A borrow is not a generic argument (breaking):** `Vec[&Str]`, `Opt[&Str]` and `Vec[&Str or None]` would store a
  borrow, and are a second-class borrow error (E2). A generator's yield (`Gen[&Str]`) and a function type's signature
  (`FunRef[(&T), Bool]`) name a borrow without storing one, so they still may. An error inside a generic instance now
  also shows where that instance was asked for ("Instantiated here").
- **Fixed:** spreading a temporary tuple, `sum(..g())` or `(0_s32, ..g())`, crashed the compiler. `g()` is evaluated
  once, into a temporary its elements are read from.
- **Fixed:** a constraint with its arguments written, `fun f[T: Add[S32]](x: T)`, was not met by `S32`, whose `Add`
  defaults its arguments to `Self`: the two were compared as written, `Self` against `S32`.
- **Fixed:** a pattern two levels deep over a variant of types from different modules (`is b::Apple[Some[U64]](v)` on
  `a::Zed[...] or b::Apple[...]`) could read the other member's value: the tag and the member list were in two
  different orders.
- **Fixed:** iterating a `Vec` or `View` of a variant by borrow (`loop x in v.iter_ref()` over a `Vec[Opt[S32]]`)
  crashed when an element was used: a borrow of a variant was merged into the variant around it, so its pointer was
  read as a value.
- **Fixed:** a generator yielding a borrow into a variant (`gen &x` with a yield type `&T or None`), and `get_ref()` on
  a `Single` of a variant, were internal compiler errors in code generation.
- **Fixed:** `gen &mut x` of a `&mut` parameter (`x: &mut S32`) was "Invalid Mutation" (E4), though a call accepts
  `h(&mut x)`: both now make the one check.
- **Fixed:** an open-ended slice as a generic function's default (`s: &StrView = "hello"[to 2_uz]`) crashed the
  compiler once the function was instantiated.

## Performance

- **NumEx is optimised and rewritten:** the big-number library behind every literal and comp-time value was installed
  without a build type, so it ran unoptimised in every build of the compiler, and took 23% of a compile. Division was
  done a bit at a time, copying and negating at each step. It now uses Knuth's Algorithm D, `*=` allocates `n + m` limbs
  rather than `n * m`, `+=` and `-=` work in place, and text is read and written many digits at a time. A `BigDec` read
  from text only cancels the factors of 2 and 5 its denominator can have, rather than running a whole `Gcd`. NumEx is
  0.6% of a compile now, and a project that took 4.39 s builds in 2.92 s.
- NumEx, GenEx and ColEx build as `Release` when no build type is given, so an install cannot quietly be unoptimised.
- **`$` mocks attach their `sup` blocks on first read:** the sweep used to attach every one, and about 96% were never
  read. This takes a further 5.3% off a compile (3.04 s to 2.86 s), with identical generated code.

## Fixed

- **A use-after-free while attaching `sup` blocks:** some sets of source files crashed the compiler, or failed in `std`
  with errors like "Identifier Unknown" (E26) or "Linear Value Not Consumed" (E94) that had nothing to do with the code.
  Files are compiled in sorted order, so a project could start failing just by adding or renaming a file. About 7% of
  shuffled file orders of a test project failed; now none of the 43 tried do.
- **Paths with spaces:** `spp run`, `spp test`, linking and `git` commands now quote the paths, URLs and branch names
  they pass to the shell, where a space used to split one argument into two.
- **Windows exit codes:** `spp run` and `spp test` read a program's exit status as a POSIX wait status everywhere, which
  misread it on Windows. Each platform now decodes its own.
- **Windows crash re-runs:** when a test binary crashes, `spp test` re-runs each test in its own process, which set
  `SPP_TEST_ONLY` in POSIX syntax and so could not work under `cmd`.
- **A dependency removed from `[vcs]` kept compiling:** its folder was still read, and its library still linked, until
  the folder was deleted by hand.
- **Stray files in a dependency compiled:** any `.spp` file in a checkout was read, such as one under `examples`, under
  a namespace named after its parent folder. Only a dependency's `src`, `tst` and `ffi` are read now.
- **An invalid dependency passed validation:** the error was printed and the build carried on. It now stops the build.
- **A project under a folder named `vcs` was misread as a dependency:** this got past the rule that only a type's own
  package can make it `Copy` or `Drop`, and left the project out of IDE indexing.
- **m68k programs over about 32 KB did not link:** LLVM's position-independent m68k code only reaches 16 bits, so m68k
  now builds fixed-address executables rather than PIE. Such a program also needs `split = false` under
  `[memory.stack]`, as safe stack has the same limit.

## Dependencies

- **A dependency's own dependencies are fetched:** `spp vcs` reads each dependency's `[vcs]` and carries on through what
  it declares, cycles included. Everything lands flat in `vcs/<name>`, and is compiled and linked, ffi libraries too.
  `spp test -l` and `--all-libs` can test any of them.
- **A dependency is one repository and branch (breaking):** one name declared with a different `git` or `branch`, by any
  two packages, is an error naming both, rather than one being chosen. URLs compare as written.
- **A package can only name what it declares (breaking):** a module naming a package its own `spp.toml` does not declare
  is "Dependency Not Declared" (E121), and that includes `std`, and a library naming the project using it. A value of
  an undeclared dependency's type can still be held and used, as long as `b::...` is not written.
- **Every package declares `std` (breaking):** a project or library that does not is told so by name, rather than
  failing at a prelude line, or with every `std` symbol undefined. A project named `std` is exempt.
- **A top-level namespace is one package (breaking):** one shared by two dependencies, or a dependency and the project,
  or used by both source and an ffi package, is an error before anything is parsed.
- **`[vcs]` records are checked (breaking):** `git` is required, `branch` is optional, and anything else is an error
  rather than ignored. A name can only hold letters, digits, `_` and `-`, so it cannot leave `vcs`, and `git` and
  `branch` cannot start with `-`, which git would read as an option.

## Command line

- **Dependencies are checked before building (breaking):** `spp validate` and `spp build --skip-vcs` report a declared
  dependency that has not been fetched, and tell you to run `spp vcs`. A broken checkout no longer stops the fetch that
  would repair it, as validation before a fetch only looks at the project.
- **Environment variables are checked (breaking):** spp stops at startup, before doing anything, on an `SPP_` variable
  it does not know or one with a malformed value, rather than silently ignoring a typo. `SPP_CI_` names are exempt. This
  includes `--help` and `spp config`.
- `spp config` lists the environment variables along with the `spp.toml` keys: `SPP_BACKTRACE`, `SPP_MEMORY_LIMIT_KB`,
  `SPP_NO_NETWORK_CHECK`, `SPP_TEST_MODE` and `SPP_TEST_ONLY`.
- `spp init --force` (`-f`) initialises a directory that is not empty, keeping any `spp.toml` and `main.spp` already
  there.
- `spp test` gains short forms: `-a` for `--all-libs`, `-r` for `--runner`.
- `--target` with an unknown triple suggests 25 targets rather than 8, the ones CI builds, including macOS, Windows and
  FreeBSD. A pre-commit hook keeps the two lists the same.
- `--mode` shows its choices as CLI11 prints them (`{dev,rel}`), derived from the modes the compiler has.
- `build` in `spp.toml` accepts any case (`LIB`), and an invalid one lists what is allowed.

## CI

- The nightly sanitizer job failed on every test, on a null pointer read in `checked_ptr_cast` (`ptr.ixx`), which
  stopped it finding anything else. The cast now answers null for a null pointer.
- Environment variables used only by CI are renamed to `SPP_CI_`, leaving `SPP_` for what the compiler reads. A
  pre-commit hook, `env-vars`, checks every name used in the repository is registered.
- CodeQL also scans the Python scripts.
- Bumped: `mimalloc`, `json`, `magic_enum`, `stringzilla`, `ColEx`, `GenEx` and `NumEx`.

## Internals

- A sweep of the ASTs and analysis utilities for workarounds (next-steps.md section 14) removed, among others: the
  temporary type ASTs the parser built only to convert (`TypeBinaryExpressionAst`, `TypeTupleShorthandAst`,
  `TypeArrayShorthandAst`, `TypeParenthesisedExpressionAst`, `TempTypeAst`); `ResetCache`, as a type is now resolved
  once and a later analysis only makes the checks its stage newly allows, re-resolving only a resolution that was
  provisional before the `sup` blocks were attached; the tuple a call's pack argument was carried as (a list now), and
  the comp pack carried as a tuple literal in the generic solver; the variant member orders other than the identity's;
  and the copying of visibility into symbols and instances, which now read it from their declaration. Hoisting a
  value read more than once is one helper (`expr_utils::HoistOnce`) for spreads, folds, comparison chains, `?` and
  destructures. `scopes::HeadOf` is `HeaderOf`, and `TypeIdHead` is `TypeKeyHeader`.
- Type keys lost two tags. `CompParam` only labelled a comp argument in a substitution's memo key, which `Arg` now does
  for type and comp arguments alike. `TypeBound` keyed a binding that linked to nothing, which no compile of std or the
  test suite reached; `KeyBinding` now raises an internal error there. With it goes a suspected misordering, where the
  stable key order read a `TypeBound` parameter id as text. A function prototype's `RequiredAt` is one shared pointer,
  where a raw pointer and an owned copy were kept side by side, and `TupleLiteralAst` builds its type in one place.
- `.triages/docs_walkthrough/interned-type-system.md` walks through the interned identities: the type and comp keys,
  their tags and headers, interning, substitution, unification, aliases and the stable order.
- New `spp.compiler.dependencies` is the one reader of `[vcs]`, and the CLI, the module tree and the ffi checks all ask
  it, where each used to work dependencies out from folders and paths. `tests/codegen/check-transitive-deps.sh` checks
  it end to end with real git repositories.
- A module's LLVM context is created at the start of stage 10, its first use, so a compile that stops after stage 8 (IDE
  indexing, or one with errors) does not make them.
- The C++ test harness finds `src/main.spp` by its path, rather than taking the first module.
- `BuildMode` and `BuildType` are `enum` types in `spp.compiler.out_layout`, used by every field and parameter, with
  their names derived by `magic_enum`, which replaces the fixed lists in the CLI and `!cfg`. Text is converted once,
  where a user writes it.
- New `spp::utils::env` is the one registry and reader of environment variables, and `spp::utils::shell` the one way to
  run a shell command and quote its arguments. Pre-commit rules ban reading the environment or calling `system`
  directly.
- The `sys` wrapper module covers the environment, file access and locks, the dynamic loader and exit statuses across
  POSIX and Windows, and `files` and `llvm_artefact` use it rather than platform headers.
- `CheckTargetSupport` moved from the CLI into `features`, taking a `TargetFacts` rather than asking codegen.
- Moved to the new GenEx API, where `views::cast_dynamic` and `actions::pop_front` are closure objects. The hand-rolled
  helpers in `utils/algorithms` are replaced by GenEx.
- The `cli`, `features`, `files`, `compiler`, `compiler_boot`, `cfg`, `ffi`, `llvm_target`, `llvm_artefact`,
  `module_tree` and `out_layout` modules are reformatted and documented, and dead code is removed, including the
  separate test count.
