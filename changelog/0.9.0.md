# S++ 0.9.0

## Ownership

- **Ownership is affine, not linear (breaking):** a value that moves (owned, not `Copy`) is used at most once, and
  whatever is still owned where its lifetime ends is dropped there by the compiler, as in Rust. A value no longer has to
  be consumed by hand: the "Linear Value Not Consumed" error (E94) is gone, and so are the explicit
  `std::mem::ops::drop(x)` calls it demanded (about 930 of them in SPP-STL). `drop(x)` is still there to end a value
  early, and it ends the loans the value holds.
- **Where values are dropped:** at the end of their scope (newest first, a value's fields last field first); at a `ret`
  or `?` for every scope it leaves, and at an `exit` or `skip` for every scope up to its loop; before a write over a
  value still held (`x = v`, `p.a = v`, through `&mut`, `x@ = v`; the new value is built aside first); at a `gen`
  where a generator frame is destroyed, or before its first resume; and at the end of the statement for a temporary
  that nothing takes (borrowed, read a part off, matched by `case`, or discarded). The iterator behind
  `loop x in ...` is dropped on every way out of the loop.
- **No drop flags:** where paths meet and disagree about a value (`case` branches, the fall-through, loop exits), each
  path still holding it drops it at its end, so after the join it is held on none and a later use is E8 ("Inconsistently
  Initialized Memory Use"). Drops are decided at compile time; nothing is tracked at run time.
- **Destructuring:** a destructure binding every owned part takes the value apart whole, which also disarms the type's
  own `drop` (how a `close`-style consumer takes `self` apart: `let Self(..) = self`). One that skips an owned part
  leaves the value partly moved, and its owner drops the rest, where the "Destructure Skips Owned Part" (E105) and
  "Linear Value Skipped In Destructure" (E96) errors used to refuse it. A destructure binding no part of a value moved
  on some paths only is now E8.
- **A partly moved value with its own `drop` is E106** ("Partial Move Of Destructible Value") wherever its owner ends,
  and for a field moved out of a temporary (`let a = mk().a`, `mk().a.b`), where it was an internal compiler error.
  `self` at the end of its own type's `drop` is dropped field by field, not through `drop` again.
- **`defer` is removed (breaking):** clean-up that is not a drop is a guard value whose `Drop` runs it (SPP-STL's
  `Vec::iter_mov` uses one). Its errors go with it: "Defer Terminates" (E97), "Defer In Compile-Time Function" (E98)
  and "Defer Consumes Moved Value" (E99).
- **`!must_use`:** a class marked `!must_use` (in SPP-STL: `Fail` and `Fut`) cannot be discarded, and neither can a
  variant that may hold one (`Res`); "Discarded Value" (E95) is now only for these, where it applied to every
  discarded value but a `Void` or `Never` one (`x` alone on a line, `[1, 2, 3]`). Any other discarded value is
  dropped. `must_use` is in the prelude.
- **A `Copy` type cannot have a destructor:** superimposing both `Copy` and `Drop` on one type is the new E131
  ("Superimposition Copy And Drop").
- **A pattern guard may move a value:** the move holds on every path past its branch, and where the guard never ran
  (the patterns did not match) the value is dropped instead, so a later branch using it is E8. A guard still may not
  move its branch's own bindings or the `case` subject, which the next branch matches whole: "Pattern Guard Moves
  Value" (E114) is now only for those.
- **An `is` binding is a view of its subject:** in `o is Some(val as y)`, `o` keeps owning what `y` names, so `y` is
  never dropped (it used to be dropped at the end of the statement whether or not it matched), and moving `y` moves
  that part out of `o`. A subject that is not a variable is held to the end of the statement. The binding lasts to the
  end of its statement: a name it reused (an earlier `let`, a parameter, the flow-typed subject) means what it did
  again afterwards, where it could not be named (E26) or kept the narrowed type.
- **A value displaced by shadowing lives to the end of its scope.**
- **The right operand of `and` and `or` is a path of its own:** a value it moves (`flag and take(x)`) is dropped on the
  path where it did not run, and a later use is E8.
- **A field of a temporary that is only borrowed or discarded** (`f(&mk().a)`, `mk().a.len()`) leaves the temporary
  whole, dropped at the end of the statement; a field moved out of it (`let a = mk().a`) leaves the rest to drop
  there.
- **Multiple assignment reads every value before writing any target:** `a, b = b, a` swaps owned values, each moved
  once and nothing dropped.

## Language

- **A destructure infers its generic arguments from the value:** `let Box(v) = b`, `case o is Some(val)`,
  `case r of { is Pass(val) ... is Fail(err) ... }` and nested patterns (`Some(val=Some(val))`, `(Some(val as a), ..)`,
  `[Some(val as x), ..]`) work without writing `[T]`; before, only locally declared classes inferred, and the prelude's
  `Some`, `Pass` and `Fail` aliases did not. Arguments that are written are checked first and pick between variant
  members (`is A[S32](v)` over `A[S32] or A[Bool]`); one that disagrees with the value is E1, and a pattern that fits
  more than one member (`is A(v)` there) is the new E129 ("Destructure Generic Ambiguous"). Comp arguments and `type`
  alias targets are inferred too.
- **Generic arguments are inferred through forwarding:** a `&Vec[S32]` or `&[1_s32, 2_s32]` passed to a `&View[T]` or
  `&mut View[T]` parameter binds `T`. Forwarding is still only from a borrow to a borrow.
- **An object initialiser infers from inherited attributes:** `D(x=1_s32)` is `D[S32]` when `x` comes from
  `sup [U] D[U] ext Base[U]`.
- **A static call infers its receiver's generic arguments:** `Vec::from(&[1_s32, 2_s32])` and
  `std::range::Range::between(0_uz, 3_uz)` need no `[S32]` or `[USize]`. Each `sup` block declaring the method is tried
  against the arguments, its constraints ruling candidates out, and the method's own generics are inferred alongside
  (`Box::pair(1_s32, true)`). More than one fitting block is the new E130 ("Static Call Receiver Ambiguous"); nothing
  to infer from (`Vec::new()`), or a method named as a value, is still E72. A method a block inherits through its
  `ext` is not tried yet.
- **`Void` is no parameter and no argument, for closures and function types too:** `|v: Void| 1_u32` is called as
  `c()`, `FunRef[(Void,), U32]` is `FunRef[(), U32]` (a tuple a function type returns keeps its `Void`s), and
  `Res[Void, E]::map` takes `|| ...`, `|v: Void| ...` or a zero-parameter function. A `Void` argument with no
  parameter left for it (`k(nothing())` where `k` takes none) is still evaluated, then not passed, where it was E50; it
  still takes its positional slot, so `k(nothing(), 1_u32)` against `k(x: U32)` is E51.
- **A namespace is not a value:** a namespace name anywhere but left of `::` (`let x = std`) is E26, where it was let
  through when no variable had its name, and `std.print()` is E53 ("Member Access Static Operator Expected").
- **Comp-time arrays have a value identity:** an array used as a `cmp` generic argument is compared by its elements, as
  a tuple is (`[1_u64; 2_uz]` and `[1_u64, 1_u64]` are the same argument), and generic parameters inside array, object
  initialiser and call comp arguments are recognised.

## Intrinsics

- **`std::mem::ops::transmute[A, B](a: A) -> B`** reinterprets the bytes of `a` as a `B` without dropping anything. It
  is `!package`, so only std calls it (SPP-STL's `Arr::split_at`).
- **`std::mem::ops::drop` is one intrinsic overload**, the one whose marker tells the compiler that the call ends its
  argument's loans.

## Code generation

- **`Ptr[T]` has a pointer's size:** it was measured as empty, so the size and layout of `Ptr[T]` and of anything
  holding one were wrong (only `NonNull[T]` was measured as a pointer).
- **Generic `!ffi` and `!conv("C")` classes keep their written attribute order,** as non-generic ones do: their
  instances lost the class's convention and were reordered. A class with a `cmp` parameter (`Counted[cmp n: USize]`)
  could also come out with its attributes permuted.

## Diagnostics

- **An error's file path carries its line and column** (`'path/file.spp:3:5', on line 3:`), which IDE consoles turn
  into a link. The column is 1-based, in UTF-16 units as editors count it; prelude lines get none.

## Fixed

- `gen (item, x)` with a tuple literal written inline moves `item`: the move was missed, which reported `item` as
  never consumed (E94) at the end of the enclosing loop.

## Runtime and std

- **SPP-STL is affine:** explicit `drop` calls are gone, `Fail` and `Fut` are `!must_use`, `must_use` is declared in
  `std::annotations`, `Drop`'s documentation describes the new rules (a resource type offers a named, fallible consumer
  such as `close`, and keeps `drop` for "discard it"), and `Vec::iter_mov` drops what it did not yield through an
  `IterMovRest` guard.
- `benchmarks/std.rev` pins an SPP-STL with `must_use`.

## CI

- The nightly memory-suite filter runs the renamed `TestDrop*` suites.
- `tests/codegen/lib.sh` takes `STD_DIR`, a local SPP-STL checkout whose tracked changes are applied over master's;
  `check-vcs-rev.sh` pins two commits of today's std, so it no longer depends on std's history.
- The `defer` benchmark is removed.

## Internals

- `linear_utils` is removed; `drop_utils` records what each way a lifetime ends drops (`OwnedValue`, `EndRegion`,
  `OwnedUpToFn`, `OwnedUpToLoop`, `OwnedAtSuspend`, `OwnedOnJoinPath`, `IsTemporary`), and `codegen/llvm_drop` (with
  `llvm_defer` merged in) emits it (`EmitOwnedDrops`, `EmitOuterDrops`, `EmitScopeExit`, the pending temporaries).
- `case_utils::CarryGuardMoves` joins the edges a guarded branch is passed over on; `mem_utils::TakeApart` is shared by
  destructures and `case` subjects; `member_lookup` holds the member checks both `.` and `::` make.
- `check-drops.sh` covers the affine drop points (scope ends, early exits, overwrites, partial moves, temporaries,
  joins, guards, swaps, field chains, short-circuits); the differential `control` and `drops` programs use guards and
  scope-end drops in place of `defer`.
- The `test_lin_*` suites are `test_drop_*`, with tests for `!must_use`, E131, guard moves and E106 on temporaries.
