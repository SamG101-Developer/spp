# S++ 0.8.0

## Language

- **Closures are written `|…|` (breaking):** `|a: S32, b: S32 caps c, &d| a + b` and `|| -> S32 { 1 }`, as in Rust,
  not `(a: S32, b: S32 caps c, &d) a + b`. `()` is now only the empty tuple, so a closure's body may also start on the
  next line, and a `|` that starts a line opens a closure rather than continuing the line before as a bitwise or.
  `async f(a)` builds its closure the same way. SPP-STL is updated with it.
- **Constraints are joined with `and` (breaking):** `[T: Add and Sub]`, not `[T: Add & Sub]`, matching variant types'
  `or`; `&` in a type now only means a borrow. SPP-STL is updated with it.
- **`!cfg` on a `sup` block,** plain or `ext`, compiles the whole block only for the builds it names, as on a class. An
  annotation applies to a `sup` block when its target includes the new `Annotation::sup_block` (only `!cfg` does in
  std); any other is an error there, as on a class. A line of the prelude may carry `!cfg` too.
- **`F128` is only on 64-bit Linux for now (breaking):** elsewhere its maths functions called the platform's
  `long double` ones, which are not 128-bit on macOS or Windows, so `sin`, `pow`, `sqrt` and the rest linked and
  returned wrong values (and F128 arithmetic did not link on Windows). `F128` and `_f128` literals are now an unknown
  type there (E26, where a `_f128` literal crashed the compiler) until SPP-STL has its own F128 maths functions.
- **A float `!=` is IEEE's:** `x != y` is true when either is a NaN, so it is always `not (x == y)` (it was false for a
  NaN on either side, as for `==`), at compile time too. `F*::ord` is the total order (`total_cmp`): -0 below +0, and
  NaNs at the ends.

## Hardening

- **Float operations are checked, as integer ones are** (`[binary.codegen] float_checks`, on by default): a float `+`,
  `-`, `*`, `/`, `%`, `sqrt`, narrowing conversion or maths function (`exp`, `ln`, `sin`, `pow`, …; an infinity at a
  pole such as `ln(0)` is a division by zero) whose result is a NaN or infinite stops the program, naming the kind, the
  width and the operation (`float division by zero (F64 divide)`,
  `float invalid operation: the result is a NaN (F64 subtract)`,
  `float overflow: the result is infinite (F32 conversion)`). A NaN or infinity going in stops it too, and
  a conversion is only checked where the widths let it overflow (`F64` to `F32`, `U128` to `F32`). In a loop that does
  nothing observable and can vectorise, the checks move to its exit, as overflow checks do, so element-wise float loops
  still vectorise, and report "float invalid operation or overflow: the result is a NaN or infinite"; a loop that cannot
  vectorise keeps its checks where they are. In rel a `+`, `-` or `*` whose result only goes on into more checked
  arithmetic or a `sqrt` is checked there (`a * b + c` once, at the `+`); a division keeps its own check, so a
  division by zero is always reported as one. Cost against unchecked, on baseline x86-64: `a[i] = a[i] * b[i] + 1`
  1.3x, scalar float code such as `nbody` 1.7x. `float_checks = false` gives IEEE 754's non-stop arithmetic back.
- **Compile-time floats are always finite:** a `cmp` value whose float arithmetic gives a NaN or an infinity is the new
  E128, in the run-time check's terms (`0.0 / 0.0` and `x % 0.0` are invalid operations, a NaN; they were reported as
  divisions by zero), where an overflow was E16 with a meaningless value. `1.0 / 0.0` stays E90, and a literal past
  its type's range (`1e400_f64`) E16. `F64::nan()`, `inf()` and the `*_ieee` forms make non-finite values at run time
  only.
- **Windows and macOS executables are checked for ASLR and DEP** (`[binary.link] harden`): lld-link is given
  `/dynamicbase /nxcompat` (and `/highentropyva` on 64 bits), and MinGW's linker their `--dynamicbase`, `--nxcompat`
  and `--high-entropy-va` forms; the linked executable is then read back, and a PE image with a fixed or low-entropy
  load address, stripped relocations or DEP off, or a Mach-O one that is not position-independent or has an executable
  stack, fails the build, as an ELF one with mixed segments did.
- **`segments_ffi` checks Windows DLLs** the same way: one that cannot be moved or has DEP off fails the build, with how
  to relink it.
- **An ffi library check the target cannot have is left out, not refused:** `fortified_ffi` (glibc only), and
  `relro_ffi` and `segments_ffi` (ELF only, and Windows for segments) are on by default; on a target without the
  feature each is now left out with the reason in the hardening record, rather than refusing to build. Set explicitly
  in `spp.toml`, it is still an error there, naming the key to turn off.

## Command line

- **`[target.linkers]` takes a full path, spaces and all:** a path to the linker on its own is quoted for the shell
  (`"C:/Program Files/LLVM/bin/lld-link.exe"`), and a path followed by arguments is quoted inside the string. A linker
  whose program is not there (neither an executable file nor on `PATH`) stops the build before linking, saying which
  entry named it, where it used to fail inside the link command.
- **`spp vcs` fetches from the repository `spp.toml` names:** each dependency is fetched from its declared URL rather
  than from whatever the checkout's `origin` was, and `origin` is pointed at it. A checkout of another repository that
  cannot be fetched is refused rather than used; an unreachable repository falls back to the existing checkout with a
  warning, as before. A branch is brought up to date by fast-forward only, and a pinned commit is checked out
  detached. A build that skips the fetch (`--skip-vcs`) refuses a branch dependency checked out on another branch, as
  it does a pin on another commit.

## Fixed

- **An error in the prelude is quoted, and says what it means:** when the prelude names something std does not define (a
  compiler and std that do not match), every program failed with an error "at the end of the file" in its own
  `main.spp`, quoting nothing. The prelude's line is now quoted, "in the prelude every file imports (this compiler and
  its std do not match)".
- **A `cmp` value from a generic `cmp fun` reading `Self::…` crashed the compiler** (`cmp k: F64 = F64::nan()`, "no
  numeric bounds for this type"): the folded body is the template's, and a call in it now reads `Self` and the
  template's parameters as the type it was called on.
- **A bare `ret` in a function returning a value passed analysis** (`fun f() -> S32 { ret }`): it was checked against
  `Void` rather than the function's return type.
- **A `!private` static method was callable from anywhere** as `Type::fn()`: a `::` access now checks visibility as a
  `.` access does (visible if any `sup` block declaring the name is). A `::` after a value that is not a namespace path
  (`f()::x`, `a.b::x`) crashed the compiler; it is now the error for a namespace access on a value.
- **A coroutine destroyed before it was ever resumed leaked its by-value parameters:** they are dropped, newest first,
  for a generic coroutine's instantiations too.
- **Moving out of an `Arr` element by element (`iter_mov`, `reverse_iter_mov`) leaked and misread:** a loop left
  part-way
  leaked every element not yet yielded, and the array was read through its first element's bytes as though they were
  its address. The rest are now dropped, and the array is read where it is.
- **A value dropped by a closure, a coroutine frame or a container could skip its destructor:** a closure dropped
  uncalled drops what it captured by value, and a coroutine destroyed at a suspension what its frame owns, but where
  nothing written in the program called that type's `drop`, its destructor was never instantiated and the value was
  destroyed field by field: a `Vec` freed its buffer without dropping its elements. Each now instantiates it.
- **A closure passed to a call was taken to be kept by the call's result** when that result cannot hold a borrow (a
  `Str`, a `Res[S32, E]`), so a later use of what it captured by borrow was a spurious borrow error. Only a result
  that can hold one (a closure, a generator, a future, or a type holding one) keeps it.
- **A struct passed to `bit_cast`** (`bit_cast[B](A(…))`) crashed the compiler with `Invalid bitcast`. `bit_cast` is
  now bounded to `BitCastable` (the sized numbers and `F8`) in SPP-STL, so it is an error where it is written.
- **A long-running compiler process could skip a check after an error:** recursion guards held in thread-wide sets were
  not cleared when an error was raised through them, so a later compile in the same process (the language server,
  `spp_tests`) could take one of its types for one already being laid out and skip it, `!ffi` attribute checks
  included. Every such guard now clears itself on the way out.

## Runtime and std

These ship in SPP-STL (`ffi/sppc` and `src/std`), which a project fetches into `vcs/std`. A project built with float
checks on needs an SPP-STL whose runtime names the float checks (sppc `0x20` to `0x23`, and the maths functions).

- **sppc** reports the float checks: invalid, division by zero, overflow, and "a NaN or infinite" for a deferred one,
  each with the operation (`add` … `remainder`, `square root`, `conversion`, `exp`, `log`, `sin`, `pow`, …) and the
  width.
- **The float API for checked arithmetic** mirrors the integer one, for `add`, `sub`, `mul`, `div`, `rem`, `sqrt` and
  every maths function: `*_ieee` (IEEE's non-stop result, unchecked, as `*_wrapping`), `*_raised` returning the result
  and whether it would have stopped (as `*_overflow`), and `*_checked` returning an `Opt` (as `*_checked`). New
  `nan()`, `inf()`, `neg_inf()`, `is_nan`, `is_infinite` and `is_finite`; `from_ieee` narrows with no check;
  `pow_ieee(Self)` and `atan2_ieee`. `asinh`, `acosh` and `atanh` return the value (they returned an `Opt`), checked,
  and no longer overflow on the way for large arguments. `round_even` rounds half to even, `minimum` and `maximum` are
  IEEE 754-2019's (a NaN wins, -0 below +0), and `pow(S32)` is computed by squaring. Parsing a float that overflows
  gives an infinity.
- **Maths constants:** `std::consts::Consts[T]` has `e`, `pi`, `tau`, `ln_2`, `ln_10`, `log2_e`, `log10_e`, `log2_10`,
  `log10_2`, `sqrt_2`, `frac_1_sqrt_2`, `frac_pi_2`, `frac_pi_4`, `frac_1_pi`, `frac_2_pi` and `frac_2_sqrt_pi` for
  `F16`, `F32`, `F64` and `F128`, each rounded once.
- **`Limits[F*]::nan`, `infinity` and `neg_infinity` are removed (breaking):** they were `0.0` placeholders; use
  `F*::nan()`, `inf()` and `neg_inf()`.
- **Integers parse from text:** `S32::try_from(&text)` and the other sized integers return `Opt[Self]` from decimal
  text, and `from_str_radix(&text, radix)` takes a base from 2 to 36; the most negative value parses.
- **Locks run a closure (breaking):** `Mutex::with_lock`, `RwLock::with_read` and `with_write`, `SpinLock::with_lock`,
  with `try_` and `timed_` forms (and `Mutex::with_lock_when`), hold the lock for exactly as long as the closure runs,
  and hand it
  a borrow of the value that cannot outlive the call or reach another thread. The owned guards they replace could do
  both, and `lock()` as a coroutine released the mutex before the borrow it yielded was used.
- **Names from the operating system are `std::os::os_string::OsStr` (breaking):** environment values, arguments and
  paths need not be UTF-8, and were copied into a `Str` unchecked, so a `Str` could hold bytes that are not UTF-8.
  `OsStr` holds them exactly: any bytes on Unix, WTF-8 on Windows (where a lone surrogate in a name used to become
  U+FFFD, so the file could not be opened again). `to_str()` gives the text if it is UTF-8, `to_str_lossy()` replaces
  what is not, and `OsStr::from(&StrView)` goes the other way. The environment, arguments and working directory moved
  to `std::os::env` (`get_env`, `set_env`, `unset_env`, `args`, `get_cwd`, `set_cwd`, from `std::process` and
  `std::fs::file`); `std::process::get_env` stays for now, giving lossy text. `Path` holds an `OsStr`: `file_name`,
  `file_stem` and `extension` return `Opt[OsStr]` (`None` for no name, or no extension, which a leading dot is not),
  `components` a `Vec[OsStr]`, and `with_file_name` and `with_extension` take an `&OsStr`. `std::os::consts` has
  `path_sep` and `path_list_sep`, and `Str` has `from_utf8_lossy`.
- **A name with a NUL inside is refused:** C stops at the first NUL, so a path or environment variable holding one was
  acted on as a shorter name, a different file or variable. A path with one now fails with the new `PathNulErr` (or is
  `false`, for `exists` and the `is_*` checks), and `set_env`, `get_env` and `unset_env` never set or read such a name
  or value.
- **A `Str` is always valid UTF-8 (breaking):** `Str::from_c_str` returns `Res[Str, Utf8Err]`, as `Str::from_utf8`
  does, where it copied whatever a C library returned (`Str::from_c_str_lossy` replaces what is not valid); the
  overload taking a `NonNull[U8]` is no longer public. `Str::new_filled` and `new_filled_in` take a `Char` rather than
  a byte, and `take_last` removes and returns the last `Char` (it removed one byte, which could split a character).
- **Fixed in std:** cloning a `Vec` of values that own memory (and `from` a view of them, `append_many`,
  `insert_many_at`) copied the values' bytes rather than cloning them, so two `Vec`s freed the same storage; `between`
  with a negative step walks down (and yields nothing walking away or standing still); arrays compare element by
  element; `fold_first`, `min` and `max` on iterators; and `Str * n` repeats a string.
- **The allocators' typed methods are `!package` (breaking):** `allocate`, `allocate_zeroed`, `deallocate` and
  `reallocate` hand out raw storage, so only std's containers call them.

## CI

- The nightly run starts at 03:00 UTC, an hour earlier.
- A `commit-msg` pre-commit hook checks commit subjects against the PR title format (`type(scope): description`),
  reading the types and the pattern from `pr_title.yaml`, which now allows `meta`.
- SonarQube analyses the C++ modules (`sonar.cfamily.enableModules`).
- Pinned dependencies: LLVM 23.1.6 on Windows, the `qemu-user` build, `mimalloc`, `nlohmann/json`, `toml++`,
  `magic_enum`, `CLI11` and `GenEx` (whose `span` and `subrange` now deduce their element and iterator types); the
  GitHub actions and the Python tools are bumped.

## Internals

- `llvm_fn_impls.cpp` emits a float check as one hot `uno (r - r), 0` branch to a cold classifier naming the kind
  (`EmitFloatCheck`, `EmitFloatNotFinite`; a division's zero-divisor and a maths function's pole tests are built
  only there), with `float_*_ieee`, `float_*_raised` and `fptrunc_ieee` intrinsics beside the checked ones, and `une`
  for `!=`. `RuntimeCheck` has `FloatInvalid`, `FloatDivideByZero`, `FloatOverflow` and `FloatNotFinite`.
- `llvm_pass_air.cpp` defers float checks (`FloatCheckOf`, `FloatAbortBehind`; only where `CanVectoriseFloats`), and
  the new `ElideChainedFloatChecksPass` drops a check its checked user covers (`PassesNonFinite`), never one inside a
  classifier. `IsAbortPath` (`llvm_pass_loop_versioning.cpp`) is the one test of whether an exit only aborts, used by the
  bounds pass and the deferral, and `VersionLoop` gives the copied loop its own copy of a whole abort path.
- New `ScopedInsert` and `ScopedAssign` (`spp.utils.functions`) for every recursion guard and saved value; the
  compiler's own guards (`CompTimeResolutionGuard`, `InstantiationDepth`, `PackElementCloneGuard`, and the alias,
  constant and member-key guards) are built on them.
- `FindProgram`, `FindCommand`, `FindNewestVersion` and `PathListSeparator` moved from `utils::files` to
  `utils::shell`, and `SharedLibraryName` into `compiler/ffi.cpp`.
- `ErrorFormatter` quotes a line of the prelude; `PreludeFor` reads a `use` behind an annotation, and the test harness
  has `!cfg` applied.
- `FloatLiteralAst::NonFinite` marks a folded NaN or infinity for E128; `UnifyTypeIds` binds a folded template's
  `Self` for the calls in its body.
- `SupPrototypeFunctionsAst` and `SupPrototypeExtensionAst` hold `Annotations` (parsed, cloned, analysed, and dropped
  by `!cfg` with the whole block); `kSupCtx` is the annotation target bit.
- `TypeSymbol::CanHoldBorrows`; `EmitSuspendDestroy` (`llvm_defer`) destroys a coroutine frame at a suspension or at
  its initial one (`_OwnedAtStart`); `GenExpressionAst::SetOwnedAtSuspend` for a builtin coroutine's body;
  `drop_utils::EnsureDropInstantiated` at each site that synthesises a drop.
- `UnhardenedImage` (`llvm_artefact`) reads a PE or Mach-O image's hardening flags; `TargetIsGlibc`, `TargetIsElf` and
  `TargetIsMachO` replace `TargetIsMusl`; `features::LeaveOutOrRefuse`.
- `dependencies::FindCheckedOutBranch` reads a checkout's branch from `.git/HEAD`.
- New codegen check `check-float-checks.sh`; `check-drops.sh` covers coroutines destroyed before they start, `iter_mov`
  left part-way and destructors nothing written calls; `intrinsics.py` covers every new intrinsic and its trap cases;
  `lib.sh` takes `STD_BRANCH` and `SPPC_LIB`; `tests/differential/floats.spp` has NaN, infinite and overflowing inputs.
- New gtest suites `test_msc_bit_cast.cpp` and `test_msc_image_hardening.cpp`, and float, `!cfg`, prelude and
  error-location cases; the error-location check fails an error placed in the prelude.
- New benchmark `codegen/checked_float_scale`.
