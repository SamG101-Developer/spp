# S++ 0.2.0

The first version published as a release. From here on every code change to `master` ships a binary, and the pipeline
refuses a merge that does not say which version it is.

## Releases

- Merging to `master` now builds one binary per platform and publishes it as a GitHub release, tagged `v<version>`
  and titled `S++ <version>`, with this file as its body. Platforms are `linux-x64`, `linux-arm64`, `macos-arm64` and
  `windows-x64`, each built with the toolchain native to it - gcc on Linux, clang on macOS, MSVC on Windows.
- The tag is created by the release itself, after every platform is green, so a failed build leaves nothing behind and
  the next push retries the same version.

## Versioning

- The compiler version is single-sourced from the `VERSION` file at the repository root. `spp --version` reads it
  through a header CMake generates, so the number the binary prints and the number on the release page cannot drift.
- A pull request that changes code must bump `VERSION` and add `changelog/<version>.md`. The new "Version & Changelog"
  check enforces both, and rejects a version that moves backwards or that is already released.

## Thread Safety

- Lots of changes within the s++ compiler code to enable thread safety at compile time, preventing unsafe
  (thread-hazardous) types from being used across threads. The existing memory model allows for the overall thread
  safety to be straightforward.
