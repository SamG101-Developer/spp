# S++ 0.2.0

The first version published as a release. From here on every code change to `master` ships a binary, and the pipeline
refuses a merge that does not say which version it is.

## Thread safety

Thread safety becomes a property of a type, the way `Copy` is, checked at compile time rather than left to the
programmer.

- A value may cross a thread boundary unless `!thread_hazard` annotates it, or anything it reaches (fields). `Rc` and
  `Weak` are the only current hazards in the library.
- Closures get a nominal type of their own, providing unique functional types like normal methods/functions, allowing
  per-closure `ThreadSafe` superimposition.
- `thread::spawn` holds both of the types crossing the boundary to the marker: the function moved onto the new thread,
  and the result moved back off it by `join`.

## Shared ownership and locks

- `std::threading::arc::Arc` and `std::threading::weak::Weak` are new: the atomically counted shared owner that `Rc`
  cannot be, and its non-owning companion.
- `Mutex` and `RwLock` hold their value in a cell of their own and hand out a guard, rather than yielding a borrow from
  a coroutine. `lock` returns `Res[MutexGuard[T], ThreadErr]`, which a borrow could never have been carried in, and the
  guard releases the lock when it is dropped. Reaching the value is `guard.get()`.

## Memory and runtime hardening

- Stack clash protection, stack canaries, and safe/split stack support, each a `spp.toml` feature that is on by default
  and queried through `utils::features::Enabled`.
- `+`, `-` and `*` now trap on overflow in every profile, rather than only in debug. An algorithm that wants the old
  behaviour calls the `*_wrapping` operation explicitly.

## Type system and codegen

- Variant handling reworked: LLVM variant mechanics refactored, widening added for object initialiser arguments, and the
  cases where a variant was mishandled inside a closure or a generic argument fixed.
- Fixes for `Self` resolution, owned `self` on inherited methods, generic substitution, access to global constants,
  float literals reaching LLVM, the `case` exit block target, intrinsic naming, and coroutine lowering. The shim that
  repaired misnamed intrinsics is gone, its root cause fixed.
- Type member function handling refactored, and errors added for non-empty bodies where an empty one is required.
- `ret` inside a coroutine no longer emits invalid IR. A `GenOnce` is lowered into an ordinary call where a `gen` reads
  as the return, so a `ret` written after one landed in a block that had already returned is a second terminator. New
  "GenOnce Finishes Without Yielding" error for the other half of it: a `GenOnce` that returns on a path that never
  yielded has nothing to hand back, which its own contract forbids.

## Diagnostics and tooling

- `spp.toml` validation is now single-point, and reports through the same semantic error machinery as everything else.
- Nicer progress bars, and a tidier entry point.

## Performance

- RTTI replaced throughout with the kind tags each AST node already carries.
- Type lookup caching, container tuning, and a large reduction in AST cloning - the three places the profile said the
  time was going.

## Dependencies

- Boost's multiprecision numbers dropped, `stringzilla` adopted, and the legacy Boost workaround removed.
- Pins refreshed, including the move to `ankerl` 4.11.

## Releases

- Merging to `master` now builds one binary per platform and publishes it as a GitHub release, tagged `v<version>`
  and titled `S++ <version>`, with this file as its body. Platforms are `linux-x64`, `linux-arm64`, `macos-arm64` and
  `windows-x64`, each built with the toolchain native to it - gcc on Linux, clang on macOS, MSVC on Windows.
- The tag is created by the release itself, after every platform is green, so a failed build leaves nothing behind and
  the next push retries the same version.

## Versioning

- The compiler version is single-sourced from the `VERSION` file at the repository root. `spp --version` reads it
  through a header CMake generates, so the number the binary prints and the number on the release page cannot drift.
- A pull request that changes code must bump `VERSION` and add `changelog/<version>.md`. The new "Version & Changelog"
  check enforces both, and rejects a version that moves backwards or that is already released.
