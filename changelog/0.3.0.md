# S++ 0.3.0

## Generics

A type now means what it resolved to where it was written, rather than what its spelling happens to name where it is
read. This closes a class of bug where a caller's `Vec[T]`, substituted into a callee whose own parameter was also
spelled `T`, silently became the callee's `T`.

- A generic parameter carries an identity of its own, independent of its name, and a binding records which parameter it
  binds. Two parameters spelled the same in different declarations are no longer taken for one another.
- A written name records the symbol it resolved to, so reading it from another scope asks what that symbol means there
  instead of resolving the spelling again.
- An instantiation is filed under what its arguments resolve to rather than how they are spelled. `Vec[Str]` is one type
  however it is written, while `Box[T]` named in a class and in a `sup` block over that class are correctly two.
- Comparison, substitution and name mangling all consult those identities, so a mangled name no longer depends on the
  spelling at the use site.
- A `cmp` generic argument is keyed by the value it folds to, so `2_uz`, `1_uz + 1_uz`, and an `n` bound to `1_uz` name
  one instantiation, while the same expression under two different bindings of `n` names two.
- Superimposition blocks are attached lazily and remembered, instead of being re-derived on every read.

### Generic arguments and parameters are one class each

The seven generic-argument AST classes are now a single `GenericArgumentAst`, and the nine generic-parameter classes a
single `GenericParameterAst`: keyword versus positional, type versus `cmp`, and required, optional or variadic are
fields rather than separate types. 28 files were removed.

## Async and await

- `await` is a new keyword, written as a postfix operator: `fut.await`. Only a `Fut` can be awaited, and anything else
  is the new "Await Target Not Future" error.
- `async f(a, b)` lowers to `Fut[T]::spawn` over a closure that makes the call, rather than passing the target and its
  arguments to `sppc::async`.

## Default values

- A default parameter or attribute value is copied into every call or object initialiser that leaves it out, so it is
  now limited to an expression that creates no scope.
- A `cmp` generic parameter's default is folded where it is declared, so a default that is not a constant is reported
  even when nothing uses it.
- A `cmp` value that depends on a `cmp` generic is folded again before it is lowered, so the emitted constant is the
  resolved value.

## `Self`

- Lots of fixes regarding how `Self` is used and translated, the stages this happens at, and unresolvable sites. Unit
  tests have increased coverage for them.

## Closures and memory analysis

- Fix linear memory analysis for closures, requiring some of the STD types to be made copyable as they should have
  already been.

## Diagnostics and tooling

- Several null pointer crashes fixed, in type comparison, type identifiers, and the AST utilities.

## CI

- A new STL conformance step starts from an empty directory and runs `spp init`, `spp build` and
  `spp test --all-libs`. It runs on one shard of each release variant and on the release build.
- Dependabot should no longer trigger massive pipeline runs like it has been on PR and merge.
- The generator for `ast_kind.ixx` and `ast_kind_range.ixx` has a `--check` mode for catching a stale generated file in
  the pre-commit hook.

## Documentation

- The compile-time safety guarantees page marks `cmp` data in `.rodata`, immutable globals and full RELRO linking as
  done, and explains how `async` and `await` relate to the concurrency guarantees.
