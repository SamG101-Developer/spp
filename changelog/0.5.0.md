# S++ 0.5.0

## Cross compilation

- **Foreign targets link:** `spp build --target <triple>` links a Linux target as it does the host, with the same
  hardening and ffi checks, where it used to stop at the object. The linker is the target's GNU cross compiler,
  `<gnu-triple>-gcc` (LLVM's `i386` and `sparcv9` are spelled `i686` and `sparc64`), or the newest versioned one
  (`...-gcc-N`) on `PATH`. `[target.linkers]` in `spp.toml` names another per target folder
  (`s390x-linux-gnu = "s390x-linux-gnu-gcc-14"`), as a command the link's arguments follow. A target that is not Linux
  still stops at the object, and says why; with no linker found, the build fails and names the package to install.
- **32-bit targets:** `USize`, `SSize` and pointers are as wide as the target's pointers. The compiler used to emit
  64-bit values for every `size_t` it built (a view's length and index, a closure environment's allocation, a coroutine
  frame's size), so on i686, x32, 32-bit ARM and MIPS every call into the runtime misread its arguments and the program
  crashed at its first allocation.
- **Fixed:** integer literal bounds were fixed to the host's at start-up, before `--target` was read, so `_uz` and
  `_sz` literals were checked as 64-bit on every target. They follow the selected target.
- riscv64 Linux is built for `rv64gc` with the `lp64d` ABI, as its libc and libraries are; the default soft-float object
  could not be linked against them.
- **Fixed:** sparc64 code generation failed with "Cannot select: load from got": LLVM's `generic` CPU is the 32-bit V8
  on SPARC. sparc64 is built for V9.
- A `musl` target skips the fortified-ffi check, as `musl` has no checked (`_chk`) libc calls.
- Built, linked and run under qemu: i686, x32, aarch64, armv7, soft-float ARM, riscv64, ppc64le, ppc64, MIPS (both byte
  orders), mips64el and loongarch64; the PowerPCs with `split = false` (below). s390x, sparc64 and m68k are not ready
  yet (see `docs/ci-production-readiness-plan.md`, P10.3).

## Conditional compilation

- **`!cfg`:** `!cfg(key="value", ...)` keeps a member of a module, class or `sup` block only when every key matches the
  build: `mode` (`dev`, `rel`), `family`, `os`, `arch`, `env`, `pointer_width` and `endian`. A value may list
  alternatives with `|` and be negated with a leading `!`: `!cfg(pointer_width="32", os="!windows")` is every 32-bit
  target but Windows. Members are dropped after parsing, before any analysis, so a dropped one may name what the target
  does not have. It applies to functions, classes, attributes, `type` and `cmp` statements and `use` imports, and is in
  the prelude.
- An unknown key is "Cfg Unknown Key" (E118), and a value no build has "Cfg Invalid Value" (E119), whether or not the
  condition holds, so a typo never silently drops a member.
- `--message-format=json` reports each member left out as an `inactive` region, from its `!cfg` to its end, in the
  indexed files, so an editor can grey out what this build does not compile. The IntelliJ plugin does.
- **Fixed:** a generic type's position ended at its name, so `Vec[S32]` spanned only `Vec`: an error on it underlined
  the name alone, and a member ending in one (`type USize = SizedIntegerUnsigned[32_u32]`) was cut short. A type ends at
  the `]` of the generic arguments written after it.

## Hardening

- **FFI libraries are checked before linking**, each check its own `[binary.link]` key, on by default, failing the link
  with the library named and how to fix it. ELF only.
  - `fortified_ffi`: the library calls a libc function unchecked (`memcpy`, `sprintf` and the like) where libc has a
    checked version, as one built without `_FORTIFY_SOURCE` does. glibc only.
  - `relro_ffi`: the library was linked without full RELRO (a `PT_GNU_RELRO` segment and `BIND_NOW`), so its GOT would
    stay writable after start-up where the program's does not.
  - `segments_ffi`: the library has a writable-and-executable segment, or code sharing a page with data.
- **An ffi package is only for the modules that ship it (breaking):** a dependency's package (`std`'s `sppc`) can no
  longer be named from the project, by a call, a `use`, a constant or a type; it is "Ffi Package Not Owned" (E120). It
  used to compile and link, as the package was linked for the dependency anyway. A project that wants the library
  directly ships the package in its own `ffi` folder. The dependency's own code still calls it.
- `[binary.link] harden` checks the linked executable itself for a writable-and-executable segment, or code sharing a
  page with data or the ELF header, rather than asking the linker to refuse them: binutils before 2.39 has no
  `--error-rwx-segments`, and before 2.31 ignores `-z separate-code` with only a warning.
- **`[target.floor] linux` (breaking):** the oldest Linux kernel the program must run on, by default RHEL 8's 4.18. A
  run-time measure that needs a newer kernel is left out, and the program's hardening record (`spp audit`) says
  `left out (why)`; on a target that is not Linux, a Linux-only measure is left out the same way. `deny_wx` (6.6)
  and `seal` (6.10) are therefore off by default, where a program used to fail at start-up on an older kernel; raise the
  floor to get them. Turning one on explicitly above the floor is a build error, not a quiet downgrade.
- **`[memory.stack] split` is refused where LLVM cannot support it:** on PowerPC (32- and 64-bit) and wasm32 LLVM has
  nowhere to keep the unsafe stack pointer. It reported an error and emitted code that wrote through whatever register
  was to hand, so ppc64le and ppc64 programs crashed at their first call. Such a target now fails in `spp.toml` until
  `split = false` is set, on by default or not.
- **Fixed:** an error LLVM reported while building the object was printed and the object linked anyway. The build now
  fails, and no object is kept.

## Loops

- **`else` (breaking):** a loop's `else` block runs whenever the loop ends without an `exit`, however many iterations it
  took first, and is the loop's value then. It used to run only when the loop never iterated.
- A loop whose `exit` gives a value needs an `else` unless its condition is `true`, as a `case` needs one: otherwise the
  condition ending it gives no value. Without one it is "Loop Missing Else" (E117).
- **Fixed:** a `skip` or `exit` in a loop whose body defers a call into std (`defer std::console::println("x")`)
  could crash the compiler. Generating the deferred call can generate the std function on demand, which moved the list
  of enclosing loops the jump was still reading its target from.
- **Fixed:** a loop's `exit`s were checked the wrong way round. `exit n` (an `Opt[S32]`) then `exit Some(val=1)` was a
  type mismatch, and the reverse was accepted with the loop typed `Some[S32]`, an internal compiler error when built. A
  later `exit` now goes into the first one's type, as the `else` block's value does.
- **Fixed:** two loops one after the other in a function shared their `exit` types, so `exit 1` in one and `exit "a"`
  in the next was a type mismatch.
- **A loop's `exit`s, a `case`'s branches and a closure's `ret`s agree on their type by one rule:** what the whole is
  assigned to, if it is (`let x: Opt[S32] = loop ..`); otherwise the widest variant among the values; otherwise the
  first value's type. Every other value must fit it. With `exit Some(val=1)` then `exit n` (an `Opt[S32]`) is an
  `Opt[S32]` loop in either order, as a `case`'s branches already were, and so is a closure with `ret Some(val=1)` and
  `ret n`; both used to be a type mismatch in the first order, and a closure took its first `ret`'s type. A loop's
  `else` is one of its values, and so is a closure body's own value when it can finish: one that does not fit the
  `ret`s is a type mismatch, where it used to be returned unchecked. A value that diverges (`!`) is none.

## Compile-time evaluation

- **Floats fold as at run time:** comp-time float arithmetic and comparisons are done in each type's own format, rounded
  to nearest, ties to even, for every width (`F8` as FP8 E4M3, `F16`, `F32`, `F64`, `F128`). A literal is the nearest
  value of its type, so `0.1_f64 + 0.2_f64 == 0.3_f64` is `false` as it is at run time, `max + 1.0` rounds back to
  `max`, two literals that round to the same value are equal, and a zero keeps its sign. A result no constant can hold
  (an infinity, or the NaN of `0.0 / 0.0`) does not fold. Floats used to fold exactly, as rationals, so a comp-time
  result could differ from the run-time one.
- **Fixed:** integer bit operations fold in the type's width, as at run time: `<<` drops the bits shifted past the top,
  `>>` is a logical shift (`-8_s32 >> 1` is 2147483644), and `~15_u32` is 4294967280, not `-16`. `<=>` gives an
  `S32` whatever its operands are, where it took their type, which for an unsigned pair cannot hold `-1`.
- `and`, `or` and `.not` fold over comp `Bool`s, including over comp generic parameters, where an operation is kept in
  the template and folded in each instance.
- A `cmp fun` call reads its comp generics as the call bound them, by keyword or position, and passes them on to the
  comptime calls it makes. `S32::zero()` and the other numeric constants are of the type they are called on.
- A `&mut` argument to a comptime call is given back the value the callee left its parameter with, as an assignment to
  the variable or attribute it came from would be, so `x += 1` and other compound assignments work in a `cmp fun`.
- In a comptime call's body, a name means what is written before it: `x is <pattern>` reads the parameter `x`, not the
  `x` the `is` narrows, and folds whether it matches or not.
- **Fixed:** constants defined through each other (`cmp a = Self::b`, `cmp b = Self::a`) overflowed the compiler's
  stack. They are "Compile-Time Constant" (E3), through a name or through `Self` alike.
- **Fixed:** a `cmp` of a variant type given one of its members (`cmp x: Opt[S32] = Some(val=1)`), or a tuple or array
  of them, failed LLVM verification. A `cmp` also gives its declared type to its value, so `[Some(val=1), Some(val=2)]`
  into `[Opt[S32]; 2]` is accepted.
- **Fixed:** a zero type's value written by name (`None`, `std::option::None`) was not a compile-time value (Invalid
  Comptime Operation, E77), so a `cmp` could not hold one, alone or in an array or tuple.

## Types

- **`F8`** is FP8 E4M3 (largest finite value 448, no infinity), stored as its bits. It converts to and from every other
  float, rounding to nearest and saturating at 448, and reads as a `U8`, but has no arithmetic or comparisons of its
  own, and the float intrinsics do not take it. It used to be lowered as a 16-bit float.
- **Fixed:** a cycle of aliases longer than one (`type A = B`, `type B = A`, or a cycle of three) hung the compiler. It
  is "Type Alias Cyclic" (E89), as `type A = A` already was.
- An alias may name one of its own parameters: `type Id[T] = T` makes `Id[Bool]` a `Bool`.
- A variadic pack among a variant's members flattens into the variant: in `fun f[..Rest](x: Bool or Rest)`,
  `f[S32, Str]` takes a `Bool or S32 or Str`, and each member widens into it. Inferred from a variant argument, the pack
  takes the members the others leave.
- An attribute whose type names a constant (`a: A[Self::n]`) is checked as the instance it keys to (`A[4_uz]`), even
  before anything else makes that instance.
- **Fixed:** a `use` of another module's `cmp` constant (`use other::m::k`) failed with "Identifier Unknown" (E26)
  on the constant's type, and a `use` of something another module had itself imported could crash the compiler.
- **Fixed:** a `cmp` constant given as a comp generic argument (`f[k]` with `cmp k: S32 = 5`) read as zero inside the
  instance, which was also a different instance from `f[5]`. A constant is now its value there, named directly, through
  its namespace, or inside a comp expression (`f[k + 1]`), which used to crash the compiler.
- **Fixed:** a private class of another module could be named in a function's signature or an attribute's type
  (`fun f(t: other::Hidden)`, `cls H { h: other::Hidden }`); only a use in a body was an "Access Violation" (E83). It is
  now E83 wherever it is written.
- `!zero_type` and `!thread_hazard` apply to classes only. On a type alias they used to mark the aliased class as well;
  they are now reported as misplaced.
- **Fixed:** a variable holding a named function took another function of the same signature (`let mut x = g` then
  `x = h`), and calling it still called `g`. That is now a type mismatch (E1); a closure still takes another closure.
- **Fixed:** a `let` with a declared type gave it to its value only after analysing it, so `[Some(val=1), None]` into
  `[Opt[S32]; 2]` was a type mismatch, and an array of named functions held its first function in every element.
- **Fixed:** an argument was analysed and generated as if it were assigned to whatever the call's result was. In
  `let y = k(case b { 1 } else { 2 })` the `case` was checked against `y`'s type, and in `let x = k({ v })` the block
  wrote `v` into `x`'s storage, past its end when `v` was wider than `x`.
- A type mismatch between two functions used as values says to declare the function type, as no order of the two can
  fit: each function has a type of its own.
- **Fixed:** a generic function named as a value in a `gen`, a `case` branch, a closure's body, or a tuple or array
  element was never instantiated, and calling it crashed.
- **Fixed:** a variant member or a named function given to an array, tuple, loop or `case` slot of a declared type is
  converted into that type. `[n, Some(val=1)]` into `[Opt[S32]; 2]` read its second element back as `None`, as did
  `[Some(val=1); 2]`; a named function in a tuple or array (`(g, 1)` into `(FunRef[..], S32)`) crashed when called; a
  loop's `else` value of a member type, or a `case` with member branches passed straight to a call, was an internal
  compiler error.

## Generators

- **Fixed:** in a `GenOnce`, which is compiled as a function returning what its `gen` yields, only a `ret` straight
  after the `gen` was left out. Any other statement after it (`gen 1` then `let x = 2`, or `{ gen 1 }` then anything)
  was generated after the return, an internal compiler error, and a `ret` after a `case` whose branches all yield raised
  "GenOnce Finishes Without Yielding" (E104). Nothing after a `gen` that returns is generated.
- **Fixed:** a private field or method used in the argument to `.res(..)` was not checked for access.
- **Fixed:** a generator dropped before it finished leaked what it still owned at the `gen` it stopped at: its
  parameters and the values in scope there. They are dropped, innermost scope and newest first, after its `defer`s. A
  `defer` that would take a value already moved by then is a "Defer Consumes Moved Value" error (E99) at that `gen`,
  where it used to be dropped twice. A value with a part moved out of it loses only the parts left; one whose type has
  its own `drop` cannot be missing a part at a `gen`, a "Partial Move Of Destructible Value" error (E106) there, even if
  the part is put back after it.
- **Fixed:** a generator borrowed `&mut` (`g: &mut Gen[S32]`) could not be resumed or looped over: `g.res()` and
  `loop x in g` were "Expression Not Generator" (E37). A `&` borrow is an invalid mutation (E4), as resuming changes the
  generator.
- **Fixed:** a variant member sent with `.res(..)` (`g.res(Some(val=1))` into a `Send=Opt[S32]`) arrived as `None`.
- A generator's `send` can be private. `.res()` reaches it through its own lowering, so calling `send` directly is an
  access error rather than a trap at runtime.

## Intrinsics

- **Fixed:** a saturating shift left by the type's width or more was poison. It gives the bound on the value's side
  (zero stays zero).
- **Fixed:** an atomic `nand` on a `Bool` left a byte that was neither `true` nor `false`.
- **Fixed:** `ctlz` counts in the width of its operand and gives a `U32`; `ctlz(0)` is that width rather than poison.

## Standard library

- `USize` and `SSize` are 32 or 64 bits by the target's pointer width, chosen with `!cfg`, and `CLong` and `CULong`
  are pointer-sized except on Windows, where they are 32 bits. The bindings generated for sppc use `CInt64` and
  `CUInt64` for C's fixed 64-bit integers.
- `Seek` works in `S64` and `U64` offsets (`seek`, `pos`, `stream_len`, `seek_from_start`, `seek_from_end`), as the file
  offsets of a 32-bit target are still 64 bits.
- `std::debug::breakpoint` is available in `rel` builds again.

## Pattern matching

- **Fixed:** a literal test evaluated the subject again. `case make() of { is (1, x) { x } else { 0 } }` called `make`
  twice, once for the subject and once inside the test of `1`, so a subject with side effects ran them twice. The
  subject is evaluated once, and every test reads it.
- **Fixed:** a literal in a variant's payload was tested whether or not the tag matched. `is Some[Str](val="abc")` on a
  `None` called `Str::eq` on whatever bytes the payload held. A literal is now tested only once its tag has matched.
- **Fixed:** a `case` over a variant name raised "Non compile-time expression" in a `cmp fun`
  (`case x of { is Pass[S32](val) { val } .. }`), as a binding read through the narrowed subject found no value.
- **Fixed:** tags were not checked at compile time, so in a `cmp fun` a `Fail` matched `is Pass(..)` when that branch
  came first. A tag is now checked against the value at its position before the pattern binds anything.
- **Fixed:** a `case` that covers every value without an `else`, and whose branches all diverge through a `!` value
  (`is S32(..) { abort() } is Bool(..) { abort() }`), was taken to fall through. Code after it was not reported as
  unreachable, and a function ending in it was rejected as missing its `ret`.

## Operators

- **Fixed:** an operand that opens scopes of its own (an `async` call, a block, a `?`) crashed the compiler under
  `.await`, indexing, slicing or a forwarded member, and under `async` as one of its call's arguments:
  `(async h()).await`, `{ async h() }.await`, `g()?[0_uz]`, `g()?.len()` and `async h(o?)` were internal compiler
  errors. `o?.await`, `o?.res()` and `{ a }.res()` raised a false "Uninitialized Memory Use" (E5). These operators built
  their call over a copy of their operand and analysed it a second time; each operand is now analysed once.
- **Fixed:** the value a `?` gives back is a temporary even when its operand is a name, so a linear one that is only
  borrowed (`o?.len()`, `o?.res()`, `o?[0_uz]@`) is "Linear Value Not Consumed" (E94), as it already was for `g()?`. It
  used to be taken for `o` itself and never required to be consumed.
- **Fixed:** a fold over anything but a name (`.. + make()`, `make() * ..`) crashed the compiler. The operand is
  evaluated once, into a temporary, and the fold reads each element off that. A call fold (`f(make())..`) evaluates its
  folded tuple once in the same way, where it used to evaluate it once per element, and one over an argument with scopes
  of its own (`f(o?)..`) no longer crashes the compiler.
- **Fixed:** an array repeat whose size is not a literal crashed the compiler as a receiver
  (`[1_u64; 1_uz + 1_uz].len()`).
- **Fixed:** dropping a closure without calling it freed its environment but not what it captured by value, which leaked
  (a captured `Str`, say, or a value whose `drop` never ran). Its captures are dropped, newest first; calling a
  `FunMov` still leaves them to its body. The runtime drops them too for a closure it gives up without calling: a task
  or thread that fails to start, and a `once` that another caller ran.
- **Fixed:** something reached through an immutable borrow that is not a variable could be mutated: `v[0_uz].bump()`
  with `bump(&mut self)`, or calling a `FunMut` as `(v[0_uz])()`. That is an invalid mutation (E4); `v[mut 0_uz]` is the
  borrow to mutate through. A method taking `&mut self` reached through a forwarding type (`Vec` to `View`) now borrows
  the forwarded value mutably, so `v[mut i]` on an owned vector no longer goes through an immutable one.

## CI

- The cross-codegen job builds for 21 targets, matching the ports of sppc: among them i686, x32, `musl`, aarch64_be,
  32-bit ARM, riscv64, the PowerPCs, s390x, MIPS in both byte orders, mips64el, sparc64, loongarch64, m68k, Windows
  (GNU), wasm32-wasip1 and FreeBSD. Each checks the object's architecture and data layout, and a Linux target its linked
  executable.
- A differential suite (`tests/differential`) builds each program at `dev` and at `rel` and compares the output,
  catching where optimisation changes behaviour: integers, floats, traps, control flow, closures, generators, `async`
  tasks, `case` patterns and folds. It runs on every pull request and after every merge.
- A program the codegen checks or the differential suite runs is killed after 60 seconds (`RUN_TIMEOUT`) and fails:
  one that hangs the same way at `dev` and at `rel` used to compare equal, and hold the job until CI timed out.
- Coverage is collected after every merge: a clang build with `SPP_COVERAGE` runs the suites, each test job keeps its
  profiles, and a `coverage` job merges them into an `llvm-cov` report, an lcov file and a summary of the totals. Sonar
  reads the report, so every analysis of master carries coverage, and the README shows its coverage badge.
- Released binaries are checked against a floor, `[floor]` in `.github/dependencies.toml` (glibc 2.28, Linux 4.18,
  binutils 2.30, macOS 11.0): a binary that needs a newer system fails the build.
- Every action is pinned by `pinact`, the pipeline's jobs are fewer and plainer, release jobs run their suites side by
  side, and macOS runners get a current bash.
- The compiler cache is a pinned release, installed with its checksum checked: ccache 4.14.2, and sccache 0.19.0 on
  Windows (`[pin.ccache]` and `[pin.sccache]`, kept current by `refresh-pins.sh`). The ccache from apt is older than
  4.14.1 and does not hash the modules a file imports, so after a module's interface changed, the clang builds were
  given the old object for each file importing it and failed to link. GCC and cl.exe module compiles are not cached by
  either tool yet (`docs/upstream-watch.md`, U11 and U12); they always compile fresh.
- CodeQL no longer reports module code falsely; the Python scripts are linted by a stricter `ruff` set and type checked
  by `ty`.
- New codegen checks: `check-intrinsics.sh` computes every numeric std intrinsic as a `cmp` constant, at run time and
  from its specification, at `dev` and `rel`, and reports which disagree; `check-fortified-ffi.sh`,
  `check-relro-ffi.sh`, `check-segments-ffi.sh` and `check-hardening-record.sh` cover the new link checks.
- `check-coercions.sh` runs a variant member and a named function through every slot a value can land in (`let`, `ret`,
  an argument, an attribute, a `gen`, a send value, a `case` branch, a closure's body, a loop's `exit` and `else`, array
  and tuple elements, nested ones, and `cmp` constants) at `dev` and `rel`, and compares what they read back as. The
  unit tests only build and verify these, so a value converted wrongly is only seen by running it.

## Internals

- A bare call (`f(..)`) finds its target from the symbol the name resolves to, by one rule: a function found nearer than
  the module (a method of the type a `sup` block extends) gives way to the module's function of that name, looked up
  where it is declared (through a `use`, its target's scope); anything else found nearer is a value being called. It
  used to rewrite the call into the function's qualified name and find the namespace again by spelling.
- A `case` is read once, at stage 7, by a `PatternSolver` (shaped like the generic and overload solvers). Its
  `MatchPlan` holds the coverage, what each branch does with the subject for the memory checks, and the tests each
  pattern makes, in order: tags, then literals. Stage 9 and stage 11 run those tests rather than walking the patterns
  again, and each literal's `eq` call is built and analysed once, rather than at every stage.
- The object pattern no longer works out its own tag checks at codegen, and the `eq` builders that rebuilt and
  re-analysed literal tests at every stage are gone.
- Postfix and unary operators share one contract for their operand, declared on the operator rather than checked by type
  in the expression: `RebuildsOperand` (the operator is handed the operand as written and owns every analysis of it:
  `?`, `async`) and `WalksOperand` (it checks the operand itself at stage 8: a method call, indexing, slicing,
  `.await`, `.res()`). `PostfixExpressionAst` and `UnaryExpressionAst` follow the same flow from those two answers.
- An operator mapped onto a method call over its analysed operand (`.await`, `.res()`, indexing, slicing, a forwarded
  member) builds that call with `PostfixExpressionAst::NewOverAnalysedLhs`, which does not analyse the operand again.
- `tests/codegen/check-case-patterns.sh` runs `case`s and checks the branch each one takes, as the gtest suite builds
  and verifies IR but never runs it.
- `tests/codegen/check-fold-operand.sh` checks a fold over a call, binary or call fold, gives the right value and runs
  the call once.
- The object-file readers return owned results rather than pointers into static buffers that were valid only until the
  next call: `UnfortifiedImport` and `UnhardenedLink` give an `Opt<Str>`, and `ReadHardeningRecord` an
  `Expected<Opt<Str>, Str>` (the record, if any, or why the file cannot be read). `GetFfiSymbolName` gives an
  `Opt<Str>` rather than an empty string for a function that is not ffi. `ArgNameOf` asserts its argument is named
  rather than answering an empty name for a positional one.
- The LLVM helpers are split by purpose: target selection, the optimisation pipeline, entry point, object artefacts and
  the codegen and memory hardening passes, in place of one `llvm_passes` file. The pointer-lowered built-in functions
  (`llvm_fn_impls`) are rewritten around shared helpers.
- Comp-time integer and float literals are made by one set of helpers, and comp-time floats are held in their type's
  format (`utils::numbers::FloatSemantics`, `ReadFloat`, `WriteFloat`), written back with the fewest digits that read
  back to the same value.
- Loops no longer track whether they were entered, now that `else` does not depend on it.
- Whether control can continue past a statement is decided by one virtual, `StatementAst::Diverges`, overridden by
  `ret`, `exit`/`skip`, blocks, `case`, `let` and expressions (typed `!`). It replaces both `Terminates()` and the free
  `expr_utils::Diverges`, which disagreed about `case`. A `case`'s answer comes from its match plan's coverage, and its
  `!` type and the codegen of a diverging branch both read it. A block's codegen stops after a member that diverges,
  which only happens where a lowered `GenOnce`'s `gen` is its return; the check in `ret` for a block that had already
  returned is gone.
- Every way out of a scope runs what it deferred through one `codegen::EmitScopeExit(into, ..)`, `into` being the scope
  control lands in: a block's parent, a function's parent for `ret` (and a generator being destroyed), the loop's own
  scope for `exit` and `skip`. It replaces `EmitDeferredScope` and `EmitDeferredUnwind` with its innermost scope and
  inclusive flag, and `ret` and `exit`/`skip` each call it once rather than on every path.
- The `defer`s a codegen walk has reached are kept in the codegen context (`LlvmCtx`, through `llvm_defer`) rather than
  on the scope, which a generic template and its instantiations share.
- A conditional loop can hold a `defer` in its own scope (`LoopDefer`), run on every way out of the loop and not between
  iterations; an iterable loop drops its iterator with one. It replaces a `defer` registered in the enclosing scope and
  taken back out by hand after the loop, at stages 8 and 11, plus a second drop after it. An
  `exit` now leaves the loop's own scope at codegen as it already did at stage 8.
- The enclosing function's return type is one value in the analysis context rather than a list that each function pushed
  onto. Generating a function never popped it, so analysis run during codegen read a stale type. A coroutine's return
  type is checked before its body.
- Codegen reads the yield type of a `gen`, the generator a `.res()` resumes, an indirect call's callee and function
  type, and a coroutine call's return type from what stage 7 resolved, instead of resolving them again.
- One coercion into a slot of a declared type, `codegen::CoerceToSlot` in the new `spp.codegen.llvm_coerce`, used at
  every slot. Its function-value, variant and structural halves are private to it, so no site converts half a value. A
  tuple or an array is converted element by element (`BuildAggregate`), told apart by identity as well as by LLVM type,
  as a named function's mock and a function value lower alike. In a constant context a variant is built in place, as a
  packed struct laid out as the variant; a `cmp` global keeps that shape and is read as its declared type
  (`LlvmVarSymbolInfo::ValueType`), through `codegen::LoadGlobalConstant`, which the three readers of a `cmp` global now
  share.
- The analysis half of that coercion, `fn_values::InstantiateFnValue`, runs at the same slots, and through tuples and
  arrays element by element.
- Whether codegen reads a value through its address is decided from its convention or its type, not from whether its
  LLVM value is a pointer: a borrowed closure being called, a borrowed argument copied into a by-value parameter, a
  closure body returning a borrowed capture, and the generator handle (`Gen` and `GenOnce` are the bare handle).
- `async` builds its future type once, at stage 7, rather than on every type query. The `?` transforms checks for a
  `Try` type and the return type are removed: the lowered calls and `ret`/`gen` already raise those errors.
- `CMakeLists.txt` is split into `cmake/` modules. `SPP_COVERAGE` builds with clang's source-based coverage.
- Fixed for other compilers: the pattern solver relied on GCC's argument evaluation order (a clang build moved a value
  before reading it), and MSVC needed fully qualified names and a plain vector for `SmallVec`.
- Dead code is removed across the AST, the parser and the scope iterator, and many more unit tests are added.
- The keys a `!cfg` condition is checked against are the compiler's own list (`cfg::CfgKeys`), as conditions are applied
  before the `cfg` annotation in std can be resolved; a test parses the annotation's parameters out of
  `annotations.spp` in std and fails if the two drift apart.
- `FloatLiteralAst::kBounds` is gone: its uses call `utils::numbers::FloatBounds()`, as the integer ones call
  `IntegerBounds()`, so the float bounds are no longer worked out at start-up on every run.
- A type written as a value (`None`) is resolved at compile time and generated once, on `TypeAst`, as the zero type's
  object initialiser, rather than by a copy in each of the three kinds of type.
- An argument is analysed, typed and generated without its caller's target (`WithoutCallersTarget`). A loop's declared
  type is kept per depth (`CompilerMetaData::LoopTargetTypes`), beside the `exit` types, which a loop now clears for its
  own depth on entry.
- A forward (`BuildFwdCall`) is told the member reached through it, and takes `fwd_mut` for a method every overload of
  which takes `&mut self`.
- After a walk that left part-way between two shadows of a name, a scope's `let` bindings are revealed as the last one
  declared (`Scope::RevealLetBindings`), as anything reading the table afterwards, such as an editor, expects.
- The builtins that are one call to a shared lowering are rows in `builtins.cpp`,
  `Register(map, name, lowering, comp_time, drops)`, rather than a declaration, a definition and a registration each:
  156 functions and the four
  `SPP_DEFINE_BUILTIN_FUNC*` macros are gone, and the registry is unchanged.
- A closure's environment carries a pointer to the function dropping its captures, beside the ownership byte, so a
  closure is dropped through its function type without a type of its own (`EmitDropClosureEnv`). sppc reads the same
  header (`sppc_closure_env`).
