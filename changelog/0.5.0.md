# S++ 0.5.0

## Cross compilation

- **Foreign targets link:** `spp build --target <triple>` links a Linux target as it does the host, with the same
  hardening and ffi checks, where it used to stop at the object. The linker is the target's GNU cross compiler,
  `<gnu-triple>-gcc` (LLVM's `i386` and `sparcv9` are spelled `i686` and `sparc64`), or the newest versioned one
  (`...-gcc-N`) on `PATH`. `[target.linkers]` in `spp.toml` names another per target folder
  (`s390x-linux-gnu = "s390x-linux-gnu-gcc-14"`), as a command the link's arguments follow. A target that is
  not Linux still stops at the object, and says why; with no linker found, the build fails and names the package to
  install.
- **32-bit targets:** `USize`, `SSize` and pointers are as wide as the target's pointers. The compiler used to emit
  64-bit values for every `size_t` it built (a view's length and index, a closure environment's allocation, a
  coroutine frame's size), so on i686, x32, 32-bit ARM and MIPS every call into the runtime misread its arguments and
  the program crashed at its first allocation.
- **Fixed:** integer literal bounds were fixed to the host's at start-up, before `--target` was read, so `_uz` and
  `_sz` literals were checked as 64-bit on every target. They follow the selected target.
- riscv64 Linux is built for `rv64gc` with the `lp64d` ABI, as its libc and libraries are; the default soft-float
  object could not be linked against them.
- **Fixed:** sparc64 code generation failed with "Cannot select: load from got": LLVM's `generic` CPU is the 32-bit V8
  on SPARC. sparc64 is built for V9.
- A `musl` target skips the fortified-ffi check, as `musl` has no checked (`_chk`) libc calls.
- Built, linked and run under qemu: i686, x32, aarch64, armv7, soft-float ARM, riscv64, ppc64le, ppc64, MIPS (both
  byte orders), mips64el and loongarch64; the PowerPCs with `split = false` (below). s390x, sparc64 and m68k are not
  ready yet (see `docs/ci-production-readiness-plan.md`, P10.3).

## Conditional compilation

- **`!cfg`:** `!cfg(key="value", ...)` keeps a member of a module, class or `sup` block only when every key matches
  the build: `mode` (`dev`, `rel`), `family`, `os`, `arch`, `env`, `pointer_width` and `endian`. A value may list
  alternatives with `|` and be negated with a leading `!`: `!cfg(pointer_width="32", os="!windows")` is every 32-bit
  target but Windows. Members are dropped after parsing, before any analysis, so a dropped one may name what the
  target does not have. It applies to functions, classes, attributes, `type` and `cmp` statements and `use` imports,
  and is in the prelude.
- An unknown key is "Cfg Unknown Key" (E118), and a value no build has "Cfg Invalid Value" (E119), whether or not the
  condition holds, so a typo never silently drops a member.

## Hardening

- **FFI libraries are checked before linking**, each check its own `[binary.link]` key, on by default, failing the
  link with the library named and how to fix it. ELF only.
  - `fortified_ffi`: the library calls a libc function unchecked (`memcpy`, `sprintf` and the like) where libc has a
    checked version, as one built without `_FORTIFY_SOURCE` does. glibc only.
  - `relro_ffi`: the library was linked without full RELRO (a `PT_GNU_RELRO` segment and `BIND_NOW`), so its GOT
    would stay writable after start-up where the program's does not.
  - `segments_ffi`: the library has a writable-and-executable segment, or code sharing a page with data.
- `[binary.link] harden` checks the linked executable itself for a writable-and-executable segment, or code sharing a
  page with data or the ELF header, rather than asking the linker to refuse them: binutils before 2.39 has no
  `--error-rwx-segments`, and before 2.31 ignores `-z separate-code` with only a warning.
- **`[target.floor] linux` (breaking):** the oldest Linux kernel the program must run on, by default RHEL 8's 4.18. A
  run-time measure that needs a newer kernel is left out, and the program's hardening record (`spp audit`) says
  `left out (why)`; on a target that is not Linux, a Linux-only measure is left out the same way. `deny_wx` (6.6)
  and `seal` (6.10) are therefore off by default, where a program used to fail at start-up on an older kernel; raise
  the floor to get them. Turning one on explicitly above the floor is a build error, not a quiet downgrade.
- **`[memory.stack] split` is refused where LLVM cannot support it:** on PowerPC (32- and 64-bit) and wasm32 LLVM has
  nowhere to keep the unsafe stack pointer. It reported an error and emitted code that wrote through whatever register
  was to hand, so ppc64le and ppc64 programs crashed at their first call. Such a target now fails in `spp.toml` until
  `split = false` is set, on by default or not.
- **Fixed:** an error LLVM reported while building the object was printed and the object linked anyway. The build
  now fails, and no object is kept.

## Loops

- **`else` (breaking):** a loop's `else` block runs whenever the loop ends without an `exit`, however many iterations
  it took first, and is the loop's value then. It used to run only when the loop never iterated.
- A loop whose `exit` gives a value needs an `else` unless its condition is `true`, as a `case` needs one: otherwise
  the condition ending it gives no value. Without one it is "Loop Missing Else" (E117).

## Compile-time evaluation

- **Floats fold as at run time:** comp-time float arithmetic and comparisons are done in each type's own format,
  rounded to nearest, ties to even, for every width (`F8` as FP8 E4M3, `F16`, `F32`, `F64`, `F128`). A literal is the
  nearest value of its type, so `0.1_f64 + 0.2_f64 == 0.3_f64` is `false` as it is at run time, `max + 1.0` rounds
  back to `max`, two literals that round to the same value are equal, and a zero keeps its sign. A result no constant
  can hold (an infinity, or the NaN of `0.0 / 0.0`) does not fold. Floats used to fold exactly, as rationals, so a
  comp-time result could differ from the run-time one.
- **Fixed:** integer bit operations fold in the type's width, as at run time: `<<` drops the bits shifted past the
  top, `>>` is a logical shift (`-8_s32 >> 1` is 2147483644), and `~15_u32` is 4294967280, not `-16`. `<=>` gives an
  `S32` whatever its operands are, where it took their type, which for an unsigned pair cannot hold `-1`.
- `and`, `or` and `.not` fold over comp `Bool`s, including over comp generic parameters, where an operation is kept in
  the template and folded in each instance.
- A `cmp fun` call reads its comp generics as the call bound them, by keyword or position, and passes them on to the
  comptime calls it makes. `S32::zero()` and the other numeric constants are of the type they are called on.
- A `&mut` argument to a comptime call is given back the value the callee left its parameter with, as an assignment to
  the variable or attribute it came from would be, so `x += 1` and other compound assignments work in a `cmp fun`.
- In a comptime call's body, a name means what is written before it: `x is <pattern>` reads the parameter `x`, not the
  `x` the `is` narrows, and folds whether it matches or not.
- **Fixed:** constants defined through each other (`cmp a = Self::b`, `cmp b = Self::a`) overflowed the compiler's
  stack. They are "Compile-Time Constant" (E3), through a name or through `Self` alike.

## Types

- **`F8`** is FP8 E4M3 (largest finite value 448, no infinity), stored as its bits. It converts to and from every
  other float, rounding to nearest and saturating at 448, and reads as a `U8`, but has no arithmetic or comparisons of
  its own, and the float intrinsics do not take it. It used to be lowered as a 16-bit float.
- **Fixed:** a cycle of aliases longer than one (`type A = B`, `type B = A`, or a cycle of three) hung the compiler. It
  is "Type Alias Cyclic" (E89), as `type A = A` already was.
- An alias may name one of its own parameters: `type Id[T] = T` makes `Id[Bool]` a `Bool`.
- A variadic pack among a variant's members flattens into the variant: in `fun f[..Rest](x: Bool or Rest)`,
  `f[S32, Str]` takes a `Bool or S32 or Str`, and each member widens into it. Inferred from a variant argument, the
  pack takes the members the others leave.
- An attribute whose type names a constant (`a: A[Self::n]`) is checked as the instance it keys to (`A[4_uz]`), even
  before anything else makes that instance.
- `!zero_type` and `!thread_hazard` apply to classes only. On a type alias they used to mark the aliased class as
  well; they are now reported as misplaced.

## Intrinsics

- **Fixed:** a saturating shift left by the type's width or more was poison. It gives the bound on the value's side
  (zero stays zero).
- **Fixed:** an atomic `nand` on a `Bool` left a byte that was neither `true` nor `false`.
- **Fixed:** `ctlz` counts in the width of its operand and gives a `U32`; `ctlz(0)` is that width rather than
  poison.

## Standard library

- `USize` and `SSize` are 32 or 64 bits by the target's pointer width, chosen with `!cfg`, and `CLong` and `CULong`
  are pointer-sized except on Windows, where they are 32 bits. The bindings generated for sppc use `CInt64` and
  `CUInt64` for C's fixed 64-bit integers.
- `Seek` works in `S64` and `U64` offsets (`seek`, `pos`, `stream_len`, `seek_from_start`, `seek_from_end`), as the
  file offsets of a 32-bit target are still 64 bits.
- `std::debug::breakpoint` is available in `rel` builds again.

## Pattern matching

- **Fixed:** a literal test evaluated the subject again. `case make() of { is (1, x) { x } else { 0 } }` called `make`
  twice, once for the subject and once inside the test of `1`, so a subject with side effects ran them twice. The
  subject is evaluated once, and every test reads it.
- **Fixed:** a literal in a variant's payload was tested whether or not the tag matched. `is Some[Str](val="abc")` on a
  `None` called `Str::eq` on whatever bytes the payload held. A literal is now tested only once its tag has matched.
- **Fixed:** a `case` over a variant name raised "Non compile-time expression" in a `cmp fun`
  (`case x of { is Pass[S32](val) { val } .. }`), as a binding read through the narrowed subject found no value.
- **Fixed:** tags were not checked at compile time, so in a `cmp fun` a `Fail` matched `is Pass(..)` when that branch
  came first. A tag is now checked against the value at its position before the pattern binds anything.
- **Fixed:** a `case` that covers every value without an `else`, and whose branches all diverge through a `!` value
  (`is S32(..) { abort() } is Bool(..) { abort() }`), was taken to fall through. Code after it was not reported as
  unreachable, and a function ending in it was rejected as missing its `ret`.

## Operators

- **Fixed:** an operand that opens scopes of its own (an `async` call, a block, a `?`) crashed the compiler under
  `.await`, indexing, slicing or a forwarded member, and under `async` as one of its call's arguments:
  `(async h()).await`, `{ async h() }.await`, `g()?[0_uz]`, `g()?.len()` and `async h(o?)` were internal compiler
  errors. `o?.await`, `o?.res()` and `{ a }.res()` raised a false "Uninitialized Memory Use" (E5). These operators
  built their call over a copy of their operand and analysed it a second time; each operand is now analysed once.
- **Fixed:** the value a `?` gives back is a temporary even when its operand is a name, so a linear one that is only
  borrowed (`o?.len()`, `o?.res()`, `o?[0_uz]@`) is "Linear Value Not Consumed" (E94), as it already was for `g()?`.
  It used to be taken for `o` itself and never required to be consumed.
- **Fixed:** a fold over anything but a name (`.. + make()`, `make() * ..`) crashed the compiler. The operand is
  evaluated once, into a temporary, and the fold reads each element off that. A call fold (`f(make())..`) evaluates
  its folded tuple once in the same way, where it used to evaluate it once per element, and one over an argument with
  scopes of its own (`f(o?)..`) no longer crashes the compiler.
- **Fixed:** an array repeat whose size is not a literal crashed the compiler as a receiver
  (`[1_u64; 1_uz + 1_uz].len()`).

## CI

- The cross-codegen job builds for 21 targets, matching the ports of sppc: among them i686, x32, `musl`,
  aarch64_be, 32-bit ARM, riscv64, the PowerPCs, s390x, MIPS in both byte orders, mips64el, sparc64, loongarch64,
  m68k, Windows (GNU), wasm32-wasip1 and FreeBSD. Each checks the object's architecture and data layout, and a Linux target its linked executable.
- A differential suite (`tests/differential`) builds each program at `dev` and at `rel` and compares the output,
  catching where optimisation changes behaviour: integers, floats, traps, control flow, closures, generators, `case`
  patterns and folds. It runs on every pull request and after every merge.
- Released binaries are checked against a floor, `[floor]` in `.github/dependencies.toml` (glibc 2.28, Linux 4.18,
  binutils 2.30, macOS 11.0): a binary that needs a newer system fails the build.
- Every action is pinned by `pinact`, the pipeline's jobs are fewer and plainer, release jobs run their suites side by
  side, and macOS runners get a current bash.
- CodeQL no longer reports module code falsely; the Python scripts are linted by a stricter `ruff` set and type checked
  by `ty`.
- New codegen checks: `check-intrinsics.sh` computes every numeric std intrinsic as a `cmp` constant, at run time and
  from its specification, at `dev` and `rel`, and reports which disagree; `check-fortified-ffi.sh`,
  `check-relro-ffi.sh`, `check-segments-ffi.sh` and `check-hardening-record.sh` cover the new link checks.

## Internals

- A `case` is read once, at stage 7, by a `PatternSolver` (shaped like the generic and overload solvers). Its
  `MatchPlan` holds the coverage, what each branch does with the subject for the memory checks, and the tests each
  pattern makes, in order: tags, then literals. Stage 9 and stage 11 run those tests rather than walking the patterns
  again, and each literal's `eq` call is built and analysed once, rather than at every stage.
- The object pattern no longer works out its own tag checks at codegen, and the `eq` builders that rebuilt and
  re-analysed literal tests at every stage are gone.
- Postfix and unary operators share one contract for their operand, declared on the operator rather than checked by
  type in the expression: `RebuildsOperand` (the operator is handed the operand as written and owns every analysis of
  it: `?`, `async`) and `WalksOperand` (it checks the operand itself at stage 8: a method call, indexing, slicing,
  `.await`, `.res()`). `PostfixExpressionAst` and `UnaryExpressionAst` follow the same flow from those two answers.
- An operator mapped onto a method call over its analysed operand (`.await`, `.res()`, indexing, slicing, a forwarded
  member) builds that call with `PostfixExpressionAst::NewOverAnalysedLhs`, which does not analyse the operand again.
- `tests/codegen/check-case-patterns.sh` runs `case`s and checks the branch each one takes, as the gtest suite builds
  and verifies IR but never runs it.
- `tests/codegen/check-fold-operand.sh` checks a fold over a call, binary or call fold, gives the right value and runs
  the call once.
- The object-file readers return owned results rather than pointers into static buffers that were valid only until
  the next call: `UnfortifiedImport` and `UnhardenedLink` give an `Opt<Str>`, and `ReadHardeningRecord` an
  `Expected<Opt<Str>, Str>` (the record, if any, or why the file cannot be read). `GetFfiSymbolName` gives an
  `Opt<Str>` rather than an empty string for a function that is not ffi. `ArgNameOf` asserts its argument is named
  rather than answering an empty name for a positional one.
- The LLVM helpers are split by purpose: target selection, the optimisation pipeline, entry point, object artefacts
  and the codegen and memory hardening passes, in place of one `llvm_passes` file. The pointer-lowered built-in
  functions (`llvm_fn_impls`) are rewritten around shared helpers.
- Comp-time integer and float literals are made by one set of helpers, and comp-time floats are held in their type's
  format (`utils::numbers::FloatSemantics`, `ReadFloat`, `WriteFloat`), written back with the fewest digits that read
  back to the same value.
- Loops no longer track whether they were entered, now that `else` does not depend on it.
- Whether control can continue past a statement is decided by one virtual, `StatementAst::Diverges`, overridden by
  `ret`, `exit`/`skip`, blocks, `case`, `let` and expressions (typed `!`). It replaces both `Terminates()` and the
  free `expr_utils::Diverges`, which disagreed about `case`. A `case`'s answer comes from its match plan's coverage,
  and its `!` type and the codegen of a diverging branch both read it.
- `CMakeLists.txt` is split into `cmake/` modules. `SPP_COVERAGE` builds with clang's source-based coverage.
- Fixed for other compilers: the pattern solver relied on GCC's argument evaluation order (a clang build moved a value
  before reading it), and MSVC needed fully qualified names and a plain vector for `SmallVec`.
- Dead code is removed across the AST, the parser and the scope iterator, and many more unit tests are added.
